# Настройка AI чата

!!! info
    AI чат требует Gramps Web API версии 2.5.0 или выше. Версия 3.6.0 ввела возможности вызова инструментов для более интеллектуальных взаимодействий.

Gramps Web API поддерживает задавание вопросов о генеалогической базе данных с использованием больших языковых моделей (LLM) с вызовом инструментов.

## Как это работает

AI помощник использует специализированные инструменты для запроса ваших генеалогических данных напрямую. Эти инструменты позволяют помощнику искать в базе данных с помощью полнотекстового поиска, фильтровать людей/события/семьи/места по конкретным критериям, вычислять отношения между индивидами и извлекать полные записи, включая заметки. Затем помощник отвечает на основе записей, которые он нашел, и ссылается на них в своем ответе. Он отвечает только на основе дерева, а не из общих знаний: если в дереве что-то не зафиксировано, помощник об этом сообщает. Ссылки на объекты, которые не существуют или являются частными для пользователя, заменяются их текстом.

AI чат не требует модели векторного встраивания. Версии Gramps Web API до 3.24 также использовали *семантический поиск* (поиск с дополнением, RAG), который сравнивал смысл вопроса с индексом числовых векторов, вычисленных для всех объектов в базе данных. Семантический поиск был удален в Gramps Web API 3.25; параметры `VECTOR_EMBEDDING_MODEL`, `VECTOR_EMBEDDING_BASE_URL` и `VECTOR_EMBEDDING_API_KEY` игнорируются и могут быть удалены из вашей конфигурации.

Для включения конечной точки чата в Gramps Web API необходимо выполнить два шага:

1. Установить необходимые зависимости,
2. Настроить поставщика LLM.

Оба шага описаны ниже по порядку. Наконец, владелец или администратор должен [настроить, какие пользователи могут получить доступ к функции чата](users.md#configuring-who-can-use-ai-chat) в настройках Управления пользователями.

## Установка необходимых зависимостей

Стандартные образы Docker для Gramps Web уже имеют все необходимые зависимости для AI чата предустановленными.

При установке Gramps Web API через `pip` (это не требуется при использовании образов Docker) необходимые зависимости устанавливаются с помощью

```bash
pip install gramps_webapi[ai]
```

## Настройка поставщика LLM

Связь с LLM использует фреймворк Pydantic AI, который поддерживает совместимые с OpenAI API. Это позволяет использовать локально развернутую LLM через Ollama (см. [Совместимость Ollama с OpenAI](https://ollama.com/blog/openai-compatibility)) или хостинг API, такие как OpenAI, Anthropic или Hugging Face TGI (Inference для генерации текста). LLM настраивается через параметры конфигурации `LLM_MODEL` и `LLM_BASE_URL`.

Кроме совместимых с OpenAI API, можно использовать префиксы моделей, специфичные для поставщика, в Pydantic AI для OpenAI, Anthropic, Google, Mistral, Groq, AWS Bedrock и Ollama. Другие поставщики, такие как Cohere, Hugging Face и xAI, не установлены; Hugging Face Inference Providers все еще могут использоваться через их совместимую с OpenAI конечную точку (`LLM_BASE_URL` установлен на `https://router.huggingface.co/v1`).

Если ваш сервер модели не ограничивает длину ответа, установите `LLM_MAX_OUTPUT_TOKENS` на максимальное количество токенов, которые модель может сгенерировать за один ответ (см. [Конфигурация](configuration.md)).

### Использование хостинга LLM через OpenAI API

При использовании OpenAI API `LLM_BASE_URL` можно оставить не установленным, в то время как `LLM_MODEL` должен быть установлен на одну из моделей OpenAI, например, `gpt-4o-mini`. LLM использует вызов инструментов для ответа на вопросы: она запрашивает базу данных напрямую, используя специализированные инструменты, и отвечает на основе записей, которые она находит. Ей не требуется глубокое генеалогическое или историческое знание. Поэтому вы можете попробовать, достаточно ли небольшой/дешевой модели.

Вам также потребуется зарегистрироваться, получить API ключ и сохранить его в переменной окружения `OPENAI_API_KEY`.

!!! info
    `LLM_MODEL` является параметром конфигурации; если вы хотите установить его через переменную окружения, используйте `GRAMPSWEB_LLM_MODEL` (см. [Конфигурация](configuration.md)). `OPENAI_API_KEY` не является параметром конфигурации, а переменной окружения, используемой непосредственно библиотекой Pydantic AI, поэтому она не должна иметь префикс.

### Использование Mistral AI

Чтобы использовать хостинговые модели Mistral AI, добавьте префикс `mistral:` к имени модели при установке `LLM_MODEL`.

Вам нужно будет зарегистрироваться для получения аккаунта Mistral AI, получить API ключ и сохранить его в переменной окружения `MISTRAL_API_KEY`. Нет необходимости устанавливать `LLM_BASE_URL`, так как Pydantic AI автоматически использует правильную конечную точку API Mistral.

Пример конфигурации при использовании docker compose с переменными окружения:
```yaml
environment:
  GRAMPSWEB_LLM_MODEL: mistral:mistral-large-latest
  MISTRAL_API_KEY: ваш-mistral-api-ключ-здесь
```

### Использование локальной LLM через Ollama

[Ollama](https://ollama.com/) — это удобный способ запускать LLM локально. Пожалуйста, обратитесь к документации Ollama для получения подробной информации. Обратите внимание, что LLM требуют значительных вычислительных ресурсов, и все, кроме самых маленьких моделей, вероятно, будут слишком медленными без поддержки GPU. Поскольку помощник полагается на вызов инструментов, выбирайте модель, которая поддерживает инструменты, такие как [`qwen2.5`](https://ollama.com/library/qwen2.5). Начните с небольшой вариации, такой как `qwen2.5:7b`, и попробуйте более крупную, если ответы недостаточно хороши. Пожалуйста, делитесь любым опытом с сообществом!

При развертывании Gramps Web с помощью Docker Compose вы можете добавить сервис Ollama и указать Gramps Web на него:

```yaml
services:
  grampsweb: &grampsweb
    # ... существующая конфигурация ...
    environment:
      GRAMPSWEB_LLM_MODEL: ollama:qwen2.5:7b
      GRAMPSWEB_LLM_BASE_URL: http://ollama:11434/v1/

  grampsweb_celery: &grampsweb_celery
    # ... существующая конфигурация ...
    environment:
      GRAMPSWEB_LLM_MODEL: ollama:qwen2.5:7b
      GRAMPSWEB_LLM_BASE_URL: http://ollama:11434/v1/

  ollama:
    image: ollama/ollama
    container_name: ollama
    ports:
      - "11434:11434"
    volumes:
      - ollama_data:/root/.ollama

volumes:
  ollama_data:
```

После запуска сервисов загрузите модель в Ollama:

```bash
docker compose exec ollama ollama pull qwen2.5:7b
```

Несколько моментов, которые следует отметить:

- Установите `LLM_MODEL` на имя модели Ollama, включая ее тег (часть после двоеточия, например, `7b`), с префиксом `ollama:`. Префикс заставляет Pydantic AI использовать свои настройки, специфичные для Ollama, для модели, что является рекомендуемой настройкой.
- `LLM_BASE_URL` должен заканчиваться на `/v1/`, например, `http://ollama:11434/v1/`.
- С префиксом `ollama:` ни `OPENAI_API_KEY`, ни переменная окружения `OLLAMA_BASE_URL` не нужны. Если `LLM_BASE_URL` не установлен, Gramps Web возвращается к `OLLAMA_BASE_URL`.
- В качестве альтернативы вы можете опустить префикс (например, `LLM_MODEL: qwen2.5:7b`) и использовать Ollama через его общий совместимый с OpenAI API. В этом случае вам также нужно будет установить переменную окружения `OPENAI_API_KEY` на `ollama` (любое ненулевое значение подойдет).

Чтобы устранить проблемы с Ollama, вы можете включить отладочный логгирование, установив переменную окружения `OLLAMA_DEBUG=1` в окружении сервиса Ollama.

!!! info
    Если вы используете Ollama для AI чата Gramps Web, пожалуйста, поддержите сообщество, заполнив эту документацию любыми недостающими деталями.

## Дополнительные функции

### Изображения в вопросах

Если ваша модель принимает изображения, установите `LLM_VISION` на `True`, чтобы пользователи могли прикреплять изображения к своим вопросам, например, сканы записей (Gramps Web API 3.26+). Изображения уменьшаются до максимума 1568 пикселей по длинной стороне перед отправкой модели. Убедитесь, что модель действительно поддерживает ввод изображений: многие маленькие локальные модели этого не делают, и поставщик затем отклоняет вопросы с изображениями.

### Позволить помощнику предлагать изменения

С установленным `LLM_ALLOW_WRITE_PROPOSALS` на `True` (Gramps Web API 3.26+), помощник может [предлагать изменения в дереве](../user-guide/chat.md#letting-the-assistant-change-your-tree), которые пользователи применяют после их проверки. Сам помощник никогда не записывает в базу данных. Предложения предлагаются только пользователям, которым разрешено добавлять, редактировать и удалять объекты, т.е. редакторам и выше, и которым разрешено использовать чат.

Написание правильных предложений сложнее для модели, чем ответы на вопросы, поэтому протестируйте это с вашей моделью перед включением для ваших пользователей. Дополнительные инструменты также делают каждый запрос к модели несколько больше.
