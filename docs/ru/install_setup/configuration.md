# Конфигурация сервера

При использовании образа Docker по умолчанию всю необходимую конфигурацию можно выполнить из браузера. Однако в зависимости от способа развёртывания может потребоваться настроить конфигурацию сервера.

На этой странице перечислены все способы изменения конфигурации и все существующие параметры конфигурации.


## Файл конфигурации и переменные окружения

Для задания параметров можно использовать файл конфигурации или переменные окружения.

При использовании [настройки на основе Docker Compose](deployment.md) вы можете подключить файл конфигурации, добавив следующий элемент списка под ключом `volumes:` в блоке `grampsweb:`:

```yaml
      - /path/to/config.cfg:/app/config/config.cfg
```
где `/path/to/config.cfg` — путь к файлу конфигурации в файловой системе вашего сервера (правая часть указывает путь в контейнере, её нельзя изменять).

При использовании переменных окружения:

- добавьте префикс `GRAMPSWEB_` к имени каждого параметра, чтобы получить имя переменной окружения;
- используйте двойное подчёркивание для вложенных параметров словаря, например `GRAMPSWEB_THUMBNAIL_CACHE_CONFIG__CACHE_DEFAULT_TIMEOUT` задаст значение параметра конфигурации `THUMBNAIL_CACHE_CONFIG['CACHE_DEFAULT_TIMEOUT']`.

Обратите внимание, что параметры конфигурации, заданные через окружение, имеют приоритет над параметрами в файле конфигурации. Если присутствуют оба варианта, «побеждает» переменная окружения.

!!! warning "Переменные окружения без префикса объявлены устаревшими"
    По историческим причинам несколько параметров — `TREE`, `SECRET_KEY`, `USER_DB_URI`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `MEDIA_BASE_DIR`, `SEARCH_INDEX_DIR`, `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `DEFAULT_FROM_EMAIL`, `BASE_URL` и `STATIC_PATH` — всё ещё можно задавать через переменные окружения *без* префикса `GRAMPSWEB_`. Это объявлено устаревшим, при запуске записывается предупреждение, а в будущем выпуске такая возможность перестанет работать. Всегда используйте форму с префиксом, например `GRAMPSWEB_TREE` вместо `TREE`.

    Обратите внимание, что это касается только переменных окружения. В файле конфигурации имена параметров всегда используются без префикса.

!!! tip "Проверка устаревших параметров"
    Устаревшие параметры конфигурации, от которых всё ещё зависит ваш сервер, например переменные окружения без префикса, `SEARCH_INDEX_DIR` или `EMAIL_USE_TLS`, при запуске записываются в журнал как предупреждения. Начиная с Gramps Web API 3.22 они также перечисляются вместе с заменой и версией, в которой поддержка будет удалена, в верхней части страницы **Системная информация** (доступной через значок пользователя на верхней панели приложения), если вы вошли в систему как администратор.

    Настройки электронной почты и базовый URL, сохранённые в базе данных мастером первоначальной настройки старых версий, также перечисляются там. Задайте их в конфигурации в соответствии со сохранёнными значениями; предупреждение исчезнет после того, как значения совпадут.

## Существующие параметры конфигурации
Существуют следующие параметры конфигурации.

### Обязательные параметры

Key | Description
----|-------------
`TREE` | Имя базы данных с семейным деревом, которую следует использовать. Выведите список доступных деревьев с помощью `gramps -l`. Если дерева с таким именем не существует, будет создано новое пустое дерево.
`SECRET_KEY` | Секретный ключ Flask. Секрет нельзя публиковать. При его изменении все токены доступа станут недействительными.
`USER_DB_URI` | URL базы данных пользователей. Допускается любой URL, совместимый с SQLAlchemy.

!!! info
    Вы можете сгенерировать безопасный секретный ключ, например, с помощью команды

    ```
    python3 -c "import secrets;print(secrets.token_urlsafe(32))"
    ```

### Необязательные параметры

Key | Description
----|-------------
`MEDIA_BASE_DIR` | Путь, используемый в качестве базового каталога для медиафайлов, переопределяющий базовый каталог медиафайлов, заданный в Gramps. При использовании [S3](s3.md) должен иметь форму `s3://<bucket_name>`
`TREE_ID` | Имя каталога базы данных семейного дерева, используемое в режиме одного дерева (когда для `TREE` не задано значение `*`). Если задано, сервер идентифицирует дерево по имени его каталога, а не по отображаемому имени, что повышает устойчивость к переименованиям. Требуется, если вы хотите переименовать дерево через API. Имя каталога можно узнать с помощью `GET /api/trees/-` (поле `id`).
`SEARCH_INDEX_DB_URI` | URL базы данных поискового индекса. В качестве серверных частей разрешены только `sqlite` или `postgresql`. По умолчанию используется `sqlite:///indexdir/search_index.db`, при этом файл SQLite создаётся в папке `indexdir` относительно пути, из которого запущен скрипт
`SEARCH_INDEX_DIR` | **Устарело** (используйте вместо этого `SEARCH_INDEX_DB_URI`). Каталог, содержащий поисковый индекс. Если задано, а `SEARCH_INDEX_DB_URI` не задано, URL поискового индекса выводится как `sqlite:///<SEARCH_INDEX_DIR>/search_index.db`.
`STATIC_PATH` | Путь, из которого следует обслуживать статические файлы (например, статический веб-интерфейс)
`BASE_URL` | Базовый URL, по которому доступен API (например, `https://mygramps.mydomain.com/`). Он необходим, например, для создания корректных ссылок сброса пароля. Для Web Push также требуется общедоступный URL HTTPS; URL по умолчанию `http://localhost/` отключает Web Push. При настройке этого параметра через окружение используйте `GRAMPSWEB_BASE_URL`.
`CORS_ORIGINS` | Источники, с которых разрешены запросы CORS. По умолчанию все запросы запрещены. Используйте `"*"`, чтобы разрешить запросы с любого домена.
`EMAIL_HOST` | Узел SMTP-сервера (например, для отправки электронных писем со ссылками на сброс пароля)
`EMAIL_PORT` | Порт SMTP-сервера. По умолчанию — 465
`EMAIL_HOST_USER` | Имя пользователя SMTP-сервера
`EMAIL_HOST_PASSWORD` | Пароль SMTP-сервера
`EMAIL_USE_TLS` | **Устарело** (используйте вместо этого `EMAIL_USE_SSL` или `EMAIL_USE_STARTTLS`). Логическое значение, указывающее, следует ли использовать TLS для отправки электронных писем. По умолчанию — `True`. При использовании STARTTLS задайте значение `False` и используйте порт, отличный от 25.
`EMAIL_USE_SSL` | Логическое значение, указывающее, следует ли использовать неявный SSL/TLS для SMTP (v3.6.0+). По умолчанию — `True`, если `EMAIL_USE_TLS` явно не задан. Обычно используется с портом 465.
`EMAIL_USE_STARTTLS` | Логическое значение, указывающее, следует ли использовать явный STARTTLS для SMTP (v3.6.0+). По умолчанию — `False`. Обычно используется с портом 587 или 25.
`DEFAULT_FROM_EMAIL` | Адрес «От» для автоматических электронных писем
`THUMBNAIL_CACHE_CONFIG` | Словарь с параметрами кэша миниатюр. Возможные параметры см. в документации [Flask-Caching](https://flask-caching.readthedocs.io/en/latest/).
`REQUEST_CACHE_CONFIG` | Словарь с параметрами кэша запросов. Возможные параметры см. в документации [Flask-Caching](https://flask-caching.readthedocs.io/en/latest/).
`PERSISTENT_CACHE_CONFIG` | Словарь с параметрами постоянного кэша, используемого, например, для телеметрии. Возможные параметры см. в документации [Flask-Caching](https://flask-caching.readthedocs.io/en/latest/).
`CELERY_CONFIG` | Параметры очереди фоновых задач Celery. Возможные параметры см. в документации [Celery](https://docs.celeryq.dev/en/stable/userguide/configuration.html).
`REPORT_DIR` | Временный каталог, в котором будут храниться результаты выполнения отчётов Gramps
`EXPORT_DIR` | Временный каталог, в котором будут храниться результаты экспорта базы данных Gramps
`BACKUP_DIR` | Каталог, в котором хранятся [резервные копии](../administration/backups.md), в отдельном подкаталоге для каждого дерева (v3.24.0+). Если параметр не задан (по умолчанию), резервные копии нельзя сохранять на сервере, но их по-прежнему можно восстанавливать из загруженного файла. Используйте постоянное расположение, например том Docker, и желательно такое, которое само резервируется или синхронизируется в другом месте.
`BACKUP_KEEP` | Количество хранимых резервных копий для каждого дерева; старые копии удаляются при создании новой (v3.24.0+). По умолчанию — `5`
`RATE_LIMIT_BACKUP` | Ограничение частоты создания резервных копий для каждого дерева (v3.24.0+). По умолчанию — `"10 per day"`
`RATE_LIMIT_MEDIA_ARCHIVE` | Ограничение частоты создания медиаархивов на странице экспорта. По умолчанию — `"1 per hour"`
`REGISTRATION_DISABLED` | Если имеет значение `True`, запрещает регистрацию новых пользователей (по умолчанию `False`). Начиная с Gramps Web API 3.26, страница входа также скрывает ссылку регистрации.
`PROXY_FIX_X_FOR` | Количество доверенных обратных прокси перед Gramps Web (v3.26.0+). Установите значение `1` при использовании одного обратного прокси, чтобы ограничения частоты применялись к каждому клиенту, а не ко всем пользователям вместе. По умолчанию — `0`. Устанавливайте этот параметр только в том случае, если сервер доступен исключительно через эти прокси.
`DISABLE_TELEMETRY` | Если имеет значение `True`, отключает сбор статистики телеметрии (по умолчанию `False`). Подробности см. в разделе [телеметрия](telemetry.md).
`PILLOW_MAX_IMAGE_PIXELS` | Задаёт параметр `PIL.Image.MAX_IMAGE_PIXELS`, который определяет количество пикселей, которое может содержать обрабатываемое изображение. Подробности см. в [документации](https://pillow.readthedocs.io/en/stable/reference/Image.html#PIL.Image.MAX_IMAGE_PIXELS).
`MAX_THUMBNAIL_FILE_BYTES` | Задаёт максимальный размер файла миниатюры. По умолчанию — `50 * 1024 * 1024` (50 МБ). Его увеличение может значительно повысить потребление памяти и привести к сбоям из-за нехватки памяти или потере данных, если большие файлы распаковываются в памяти.


!!! info
    При использовании переменных окружения для конфигурации логические параметры, такие как `EMAIL_USE_SSL`, должны иметь значение только в виде строки `true` или `false` (с учётом регистра!).


### Параметры для баз данных PostgreSQL

Эти параметры обязательны, если ваши семейные деревья размещены в [базе данных PostgreSQL](postgres.md) с использованием дополнения SharedPostgreSQL.

Key | Description
----|-------------
`POSTGRES_USER` | Имя пользователя для подключения к базе данных
`POSTGRES_PASSWORD` | Пароль пользователя базы данных


### Параметры, относящиеся к размещению нескольких деревьев

Следующие параметры относятся к [размещению нескольких деревьев](multi-tree.md).


Key | Description
----|-------------
`MEDIA_PREFIX_TREE` | Логическое значение, указывающее, следует ли использовать отдельный подкаталог для медиафайлов каждого дерева. По умолчанию — `False`, но при настройке нескольких деревьев настоятельно рекомендуется использовать `True`
`NEW_DB_BACKEND` | Серверная часть базы данных, используемая для вновь создаваемых семейных деревьев. Должна иметь значение `sqlite` или `sharedpostgresql`. По умолчанию — `sqlite`. Значение `postgresql` всё ещё принимается, но объявлено устаревшим, поскольку серверная часть PostgreSQL будет удалена в Gramps Web API 4.0.
`POSTGRES_HOST` | Имя узла сервера PostgreSQL, используемого для создания новых деревьев при настройке нескольких деревьев с серверной частью SharedPostgreSQL
`POSTGRES_PORT` | Порт сервера PostgreSQL, используемого для создания новых деревьев при настройке нескольких деревьев с серверной частью SharedPostgreSQL


### Параметры аутентификации OIDC

Эти параметры необходимы, если вы хотите использовать аутентификацию OpenID Connect (OIDC) с внешними поставщиками. Подробные инструкции по настройке и примеры см. в разделе [Аутентификация OIDC](oidc.md).

Key | Description
----|-------------
`OIDC_ENABLED` | Логическое значение, указывающее, следует ли включить аутентификацию OIDC. По умолчанию — `False`.
`OIDC_ISSUER` | URL издателя OIDC (для пользовательских поставщиков OIDC)
`OIDC_CLIENT_ID` | Идентификатор клиента OAuth (для пользовательских поставщиков OIDC)
`OIDC_CLIENT_SECRET` | Секрет клиента OAuth (для пользовательских поставщиков OIDC)
`OIDC_NAME` | Пользовательское отображаемое имя поставщика. По умолчанию — "OIDC"
`OIDC_SCOPES` | Области OAuth. По умолчанию — "openid email profile"
`OIDC_USERNAME_CLAIM` | Утверждение, используемое для имени пользователя. По умолчанию — "preferred_username"
`OIDC_OPENID_CONFIG_URL` | Необязательно: URL конечной точки конфигурации OpenID Connect (если не используется стандартный `/.well-known/openid-configuration`)
`OIDC_PKCE` | Логическое значение, указывающее, следует ли использовать PKCE. Если не задано, PKCE используется, когда документ обнаружения поставщика содержит `S256`. См. раздел [PKCE](oidc.md#pkce)
`OIDC_DISABLE_LOCAL_AUTH` | Логическое значение, указывающее, следует ли отключить локальную аутентификацию по имени пользователя и паролю. По умолчанию — `False`
`OIDC_AUTO_REDIRECT` | Логическое значение, указывающее, следует ли автоматически перенаправлять пользователя к OIDC, если настроен только один поставщик. По умолчанию — `False`
`OIDC_ALLOWED_REDIRECT_URIS` | Список URI `https`, по которым нативные приложения могут получать результат входа (v3.26.0+), задаваемый в переменной окружения в виде списка JSON. По умолчанию пуст. Требуется только в том случае, если это указано в документации нативного приложения. См. раздел [Нативные приложения](oidc.md#native-apps)

#### Встроенные поставщики OIDC

Для встроенных поставщиков (Google, Microsoft) используйте следующие параметры:

Key | Description
----|-------------
`OIDC_GOOGLE_CLIENT_ID` | Идентификатор клиента Google OAuth
`OIDC_GOOGLE_CLIENT_SECRET` | Секрет клиента Google OAuth
`OIDC_MICROSOFT_CLIENT_ID` | Идентификатор клиента Microsoft OAuth
`OIDC_MICROSOFT_CLIENT_SECRET` | Секрет клиента Microsoft OAuth
`OIDC_GOOGLE_PKCE` | Логический параметр PKCE для Google, см. раздел [PKCE](oidc.md#pkce)
`OIDC_MICROSOFT_PKCE` | Логический параметр PKCE для Microsoft, см. раздел [PKCE](oidc.md#pkce)

#### Сопоставление ролей OIDC

Эти параметры позволяют сопоставлять группы/роли OIDC от поставщика удостоверений с ролями пользователей Gramps Web:

Key | Description
----|-------------
`OIDC_ROLE_CLAIM` | Имя утверждения в токене OIDC, содержащего группы/роли пользователя. По умолчанию — "groups"
`OIDC_GROUP_ADMIN` | Имя группы/роли у поставщика OIDC, сопоставляемой с ролью Gramps «Admin»
`OIDC_GROUP_OWNER` | Имя группы/роли у поставщика OIDC, сопоставляемой с ролью Gramps «Owner»
`OIDC_GROUP_EDITOR` | Имя группы/роли у поставщика OIDC, сопоставляемой с ролью Gramps «Editor»
`OIDC_GROUP_CONTRIBUTOR` | Имя группы/роли у поставщика OIDC, сопоставляемой с ролью Gramps «Contributor»
`OIDC_GROUP_MEMBER` | Имя группы/роли у поставщика OIDC, сопоставляемой с ролью Gramps «Member»
`OIDC_GROUP_GUEST` | Имя группы/роли у поставщика OIDC, сопоставляемой с ролью Gramps «Guest»

### Параметры только для функций ИИ

Эти параметры необходимы, если вы хотите использовать чат с ИИ. Подробности см. в разделе [Настройка чата с ИИ](chat.md).

!!! note
    Параметры `VECTOR_EMBEDDING_MODEL`, `VECTOR_EMBEDDING_BASE_URL` и `VECTOR_EMBEDDING_API_KEY`, предназначенные для семантического поиска, игнорируются начиная с Gramps Web API 3.25, в котором семантический поиск был удалён. Для чата с ИИ требуется только `LLM_MODEL`.

Key | Description
----|-------------
`LLM_BASE_URL` | Базовый URL совместимого с OpenAI API чата. По умолчанию — `None`, что означает использование API OpenAI.
`LLM_MODEL` | Модель, используемая для совместимого с OpenAI API чата. Если параметр не задан (по умолчанию), чат отключён. Начиная с v3.6.0 помощник ИИ использует Pydantic AI с возможностью вызова инструментов.
`LLM_MAX_OUTPUT_TOKENS` | Максимальное количество токенов, которое модель может сгенерировать в одном ответе. По умолчанию не задано, поэтому ограничение устанавливает сервер модели. Полезно для серверов моделей без собственного ограничения, где ответ в противном случае может продолжаться бесконечно.
`LLM_MAX_CONTEXT_LENGTH` | Ограничение количества символов в контексте семейного дерева, предоставляемом LLM. По умолчанию — 50000.
`LLM_SYSTEM_PROMPT` | Пользовательский системный запрос для чат-помощника LLM (v3.6.0+). Если не задан, используется запрос по умолчанию, оптимизированный для генеалогии.
`LLM_VISION` | Логическое значение, указывающее, могут ли пользователи прикреплять изображения к своим вопросам (v3.26.0+). Включайте этот параметр только в том случае, если модель принимает изображения. По умолчанию — `False`. См. раздел [Изображения в вопросах](chat.md#images-in-questions)
`LLM_ALLOW_WRITE_PROPOSALS` | Логическое значение, указывающее, может ли помощник предлагать пользователям изменения дерева для проверки и применения (v3.26.0+). По умолчанию — `False`. См. раздел [Разрешение помощнику предлагать изменения](chat.md#letting-the-assistant-propose-changes)


## Пример файла конфигурации

Минимальный файл конфигурации для рабочей среды может выглядеть так:
```python
TREE="My Family Tree"
BASE_URL="https://mytree.example.com"
SECRET_KEY="..."  # ваш секретный ключ
USER_DB_URI="sqlite:////path/to/users.sqlite"
EMAIL_HOST="mail.example.com"
```
