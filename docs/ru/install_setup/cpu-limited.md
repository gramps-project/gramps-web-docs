# Ограничение использования CPU и памяти

В рекомендуемой конфигурации на базе Docker Gramps Web использует [Gunicorn](https://gunicorn.org/) для обслуживания 
бэкенда и [Celery](https://docs.celeryq.dev) для фоновых задач. В обоих случаях несколько рабочих процессов 
могут выполняться параллельно, что делает приложение более отзывчивым с точки зрения пользователя. 
Однако увеличение числа рабочих процессов также увеличивает объем используемой оперативной памяти (даже когда 
приложение неактивно), а разрешение обработки запросов параллельно может привести к высокой загрузке CPU 
(в частности, когда многие пользователи используют приложение одновременно). И Gunicorn, и Celery позволяют 
ограничить количество параллельных рабочих процессов.

## Получение информации о вашей системе

На Linux вы можете проверить количество доступных ядер на вашей системе с помощью следующей команды:

```bash
lscpu | grep CPU
```

Чтобы увидеть, сколько памяти и пространства подкачки у вас доступно, используйте

```bash
free -h
```

## Ограничение числа рабочих процессов Gunicorn

Самый простой способ установить количество рабочих процессов Gunicorn при использовании 
стандартного образа Gramps Web в Docker — это установить переменную окружения `GUNICORN_NUM_WORKERS`, 
например, объявив ее в файле `docker-compose.yml` под секцией "environment".

```yaml
services:
  grampsweb:
    environment:
      GUNICORN_NUM_WORKERS: 2
```

Смотрите [документацию Gunicorn](https://docs.gunicorn.org/en/stable/design.html#how-many-workers), чтобы 
определить идеальное количество рабочих процессов.

!!! info
    Образ Docker запускает Gunicorn с опцией `--preload`, поэтому рабочие процессы делят память загруженного 
    приложения, и каждый дополнительный рабочий процесс требует меньше памяти. Если вы переопределяете команду 
    Gunicorn, оставьте `--preload`, чтобы воспользоваться этим преимуществом.

## Ограничение числа рабочих процессов Celery

Чтобы установить количество рабочих процессов Celery, измените настройку `concurrency` в файле Docker compose:

```yaml
  grampsweb_celery:
    command: celery -A gramps_webapi.celery worker --loglevel=INFO --concurrency=2
```

Смотрите [документацию Celery](https://docs.celeryq.dev/en/stable/userguide/workers.html#concurrency), чтобы 
определить идеальное количество рабочих процессов.

!!! info
    Если флаг `concurrency` опущен (что имело место в документации Gramps Web до версии 2.5.0), он 
    по умолчанию равен количеству доступных ядер CPU на системе, что может потреблять значительное количество памяти.
