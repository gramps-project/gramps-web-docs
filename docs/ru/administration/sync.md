# Синхронизация Gramps Web и Gramps Desktop

*Gramps Web Sync* — это дополнение для Gramps, которое позволяет синхронизировать вашу базу данных Gramps на настольном компьютере с Gramps Web, включая медиафайлы.

!!! warning
    Как и с любым инструментом синхронизации, не рассматривайте это как инструмент резервного копирования. Случайное удаление с одной стороны будет распространено на другую сторону. Убедитесь, что вы регулярно создаете резервные копии (в формате Gramps XML) вашего семейного дерева.

!!! info
    Документация относится к последней версии дополнения Gramps Web Sync. Пожалуйста, используйте менеджер дополнений Gramps, чтобы обновить дополнение до последней версии, если это необходимо.

!!! note "Что изменилось в версии 1.5"
    Интерфейс дополнения был переписан в версии 1.5. Пошаговый мастер исчез, его заменило одно окно, а медиафайлы теперь подтверждаются вместе с изменениями объектов, а не на отдельной странице позже. Если вы ищете селектор режима синхронизации, он теперь находится **над** списком изменений, а не под ним. Режим синхронизации **слияния** был удален; смотрите [Режим синхронизации](#sync-mode) ниже.

## Установка

Дополнение требует Gramps 6.0, работающего на Python 3.10 или новее. Оно доступно в Gramps Desktop и может быть установлено [обычным способом](https://www.gramps-project.org/wiki/index.php/5.2_Addons#Installing_Addons_in_Gramps).

!!! warning
    Пожалуйста, убедитесь, что вы используете ту же версию Gramps на вашем настольном компьютере, что и на вашем сервере. Смотрите раздел [Получить помощь](../help/help.md), чтобы узнать, какая версия Gramps работает на вашем сервере. Версия Gramps имеет форму `MAJOR.MINOR.PATCH`, и `MAJOR` и `MINOR` должны совпадать на веб-версии и настольной.

### Требования к серверу

Дополнение проверяет две вещи о вашем сервере, как только оно подключается, и отказывается продолжать, если одна из них не выполнена. Обе проверки происходят до того, как что-либо будет загружено.

- **Версия Gramps Web API 3.x.** Эта версия дополнения, для Gramps 6.0, работает с Gramps Web API 3. Существующий сервер требует обновления; сервер, работающий на *новой* основной версии API, требует более новой версии Gramps, а не более нового дополнения, поскольку каждая линия выпуска Gramps соответствует одной версии API. Вы можете найти версию вашего сервера в разделе *Настройки ▸ Информация о версии* в Gramps Web.
- **Очередь фоновых задач.** Синхронизация отправляет свои изменения как фоновую задачу. На сервере без настроенной очереди задач применение изменений будет выполняться синхронно и истечет по времени на любом реальном семейном дереве, поэтому дополнение отказывается запускаться, а не завершает работу на полпути.

Вам также нужна учетная запись с как минимум правами редактора, чтобы применять изменения к удаленной базе данных.

Дополнительный шаг:

??? note inline end "Ошибка в Gnome keyring"
    В настоящее время существует [ошибка в python keyring](https://github.com/jaraco/keyring/issues/496), которая затрагивает многие конфигурации рабочего стола Gnome. Вам может понадобиться создать файл конфигурации `~/.config/python_keyring/keyringrc.cfg` и отредактировать его так:

        [backend]
        default-keyring=keyring.backends.SecretService.Keyring

- Установите `keyring` (например, `sudo apt install python3-keyring` или `sudo dnf install python3-keyring`), чтобы обеспечить безопасное хранение пароля API в менеджере паролей вашей системы.

Если keyring не может быть использован, дополнение сообщает об этом и продолжает работу без него — вам просто будет предложено ввести ваш пароль каждый раз. В пакете Gramps **Snap** системный keyring блокируется из-за ограничений до тех пор, пока вы не подключите интерфейс один раз:

```bash
snap connect gramps:password-manager-service
```

Дополнение показывает эту точную команду, когда обнаруживает ситуацию.

## Использование

После установки дополнение доступно в Gramps в разделе *Инструменты ▸ Обработка семейного дерева ▸ Gramps&nbsp;Web&nbsp;Sync*. После подтверждения предупреждения диалога о том, что история отмены будет утеряна, открывается окно синхронизации.

**Никакие изменения не применяются к вашему локальному дереву или к серверу, пока вы явно не подтвердите их.**

В окне есть полоса в верхней части, указывающая название семейного дерева, с которым вы синхронизируетесь, учетную запись и адрес, к которому оно принадлежит, а также когда оно было в последний раз синхронизировано. Внизу отображается версия дополнения и версия веб-API сервера — полезно при сообщении о проблеме.

### Подключение

Если вы уже синхронизировали это семейное дерево ранее и ваш пароль сохранен, дополнение подключается сразу после открытия и переходит к сравнению. В противном случае оно запрашивает базовый URL вашего экземпляра Gramps Web (пример: `https://mygrampsweb.com/`), ваше имя пользователя и ваш пароль.

URL и имя пользователя хранятся в открытом виде в вашем пользовательском каталоге Gramps. Пароль хранится в менеджере паролей вашей системы только в том случае, если вы оставите установленным флажок **Запомнить пароль**; снятие флажка удаляет любой пароль, уже сохраненный для этого сервера.

!!! tip "Несколько семейных деревьев, несколько серверов"
    Каждый сервер, с которым вы синхронизируетесь, хранится отдельно, вместе с собственной записью о том, когда он был в последний раз синхронизирован. Чередование между двумя серверами больше не нарушает ни один из них.

    Каждая запись также фиксирует **какое локальное семейное дерево** было в последний раз синхронизировано. Дополнение подключается самостоятельно только тогда, когда это соответствует дереву, которое у вас открыто; в противном случае оно показывает детали подключения и ждет, пока вы нажмете *Подключиться*, с предупреждением, если сохраненные учетные данные принадлежат другому дереву. Это важно, потому что синхронизация дерева с сервером, содержащим *другое* дерево, предложит удалить содержимое обоих.

Доступны два действия, пока ничего не записывается:

- **Сменить сервер…**, на верхней полосе, возвращает к деталям подключения, чтобы вы могли указать это дерево на другом сервере. Это прерывает текущее сравнение, а не заставляет вас ждать его завершения.
- **Забыть этот сервер**, на панели подключения, удаляет сохраненный адрес, имя пользователя и пароль, а также запись о том, когда это дерево в последний раз синхронизировалось. Следующая синхронизация затем сравнивает два дерева с нуля.

Если вы введете адрес, начинающийся с `http://`, а не с `https://`, предупреждение появится по мере ввода. Ваш пароль будет отправлен в открытом виде, поэтому используйте его только для локального тестирования.

### Обзор изменений

Дополнение сравнивает локальные и удаленные базы данных и показывает, что оно предлагает сделать. В отличие от более ранних версий, которые перечисляли сырые различия между двумя деревьями, список теперь показывает **действия**, которые будут выполнены, сгруппированные по тому, какую базу данных они изменяют:

```
▾ Изменения на этом компьютере (7 объектов)
    ▾ Добавить 3 объекта
        Персона   Джон Смит        I0123
    ▾ Обновить 4 объекта
        …
▾ Изменения на сервере (5 объектов)
    …
```

Каждая строка называет объект, так что вы можете понять, кто или что затронуто, а не просто видеть ID Gramps.

Если что-то будет удалено, предупреждение над списком говорит, сколько объектов и с какой стороны. Это появляется всякий раз, когда участвуют удаления, включая обычную двустороннюю синхронизацию, которая распространяет удаление, которое вы сделали сами.

Нажмите **Применить**, чтобы выполнить то, что описано в списке.

!!! warning "Не редактируйте во время обзора"
    Окно синхронизации не блокирует остальную часть Gramps, поэтому вы можете продолжать работать, пока список открыт. Если вы редактируете затронутый объект, дополнение обнаруживает это, когда вы нажимаете Применить, останавливается, не внося никаких изменений, и просит вас сравнить снова. Ничего не потеряно, но сравнение нужно повторить.

#### Режим синхронизации

Режим синхронизации выбирается **над** списком изменений. Изменение его перестраивает список, потому что режим определяет, что каждое различие на самом деле становится.

- **Двусторонняя синхронизация** (по умолчанию) — изменения с обеих сторон комбинируются. Объекты, отредактированные в обоих местах, объединяются.
- **Сбросить сервер, чтобы он соответствовал этому компьютеру** — сервер приводится в соответствие с этим компьютером. Все, что изменено только на сервере, удаляется.
- **Сбросить этот компьютер, чтобы он соответствовал серверу** — этот компьютер приводится в соответствие с сервером. Все, что изменено только здесь, удаляется.

!!! note
    Режим **слияния**, доступный в более ранних версиях, был удален. Он отличался от двусторонней синхронизации только восстановлением объектов, удаленных с одной стороны, вместо распространения удаления, что не было отличием, которое интерфейс мог объяснить полезно. Если вы полагались на него, используйте двустороннюю синхронизацию и восстановите все, что хотите сохранить из резервной копии.

### Медиафайлы

Медиафайлы обрабатываются как часть того же подтверждения, а не как отдельный шаг. Если какие-либо файлы нужно передать, флажок под списком предлагает переместить их:

```
[x] Также передать 12 медиафайлов (4 для загрузки, 8 для выгрузки)
```

Снимите флажок, чтобы синхронизировать изменения объектов, не трогая файлы.

Файлы, отсутствующие на *обеих* сторонах, перечисляются отдельно, потому что ничего нельзя сделать с ними:

```
2 медиафайла отсутствуют на обеих сторонах и не могут быть переданы.
```

Обратите внимание на следующие ограничения синхронизации медиафайлов:

- Если локальный файл имеет другую контрольную сумму по сравнению с той, что хранится в базе данных Gramps (это может произойти, например, для файлов Word, когда они редактируются после добавления в Gramps), загрузка завершится с сообщением об ошибке.
- Инструмент не проверяет целостность всех локальных файлов, поэтому, если локальный файл существует по пути, хранящемуся для медиаобъекта, но файл отличается от файла на сервере, инструмент этого не обнаружит. Используйте дополнение Media Verify, чтобы обнаружить файлы с неправильными контрольными суммами.

### Когда что-то идет не так

Если синхронизация завершается неудачей на полпути — например, из-за разрыва соединения — дополнение сообщает, что уже было применено, и предлагает **Попробовать снова**, что возобновляет с того шага, который не удался, а не начинает заново. Загруженная копия удаленного дерева сохраняется, поэтому повторная попытка не загружает и не сравнивает ее второй раз.

Технические детали сбоя доступны за расширителем *Детали*, с кнопкой для их копирования для отчета об ошибке.

## Устранение неполадок

### Отладочный лог

Если вы сталкиваетесь с проблемами с дополнением Sync, пожалуйста, запустите Gramps с включенной отладочной записью, [запустив Gramps из командной строки](https://gramps-project.org/wiki/index.php/Gramps_5.2_Wiki_Manual_-_Command_Line) с помощью следующего параметра:

```bash
gramps --debug grampswebsync
```

Это выведет множество полезных логов в командной строке, которые помогут вам определить причину проблемы.

### Учетные данные сервера

Если подключение не удается, пожалуйста, дважды проверьте URL сервера, ваше имя пользователя и пароль.

### Дополнение отказывается подключаться

Если дополнение сообщает, что версия Gramps Web API сервера слишком старая или слишком новая, или что очередь фоновых задач не настроена, смотрите [Требования к серверу](#server-requirements) выше. Эти проверки происходят перед всем остальным, поэтому сообщение прямо указывает на проблему.

### Проблемы с правами

Если вы сталкиваетесь с ошибкой, связанной с правами, пожалуйста, проверьте роль пользователя вашей учетной записи Gramps Web. Вы можете применять изменения к удаленной базе данных, только если вы являетесь пользователем с ролью редактора, владельца или администратора.

### Неожиданные изменения в базе данных

Если инструмент синхронизации обнаруживает изменения, которые, по вашему мнению, не произошли, возможно, есть несоответствия в одной из баз данных, которые вводят Gramps в заблуждение, заставляя его обнаруживать разницу, или время не синхронизировано между вашим локальным компьютером и сервером.

Пожалуйста, проверьте, что часы на обоих устройствах правильно настроены (обратите внимание, что часовой пояс не имеет значения, так как инструмент использует временные метки Unix, которые не зависят от часового пояса).

Вы также можете запустить инструмент проверки и восстановления на вашей локальной базе данных и посмотреть, поможет ли это.

Простой, но эффективный метод, чтобы убедиться, что несоответствия в вашей локальной базе данных не вызывают ложные срабатывания, — это экспортировать вашу базу данных в Gramps XML и импортировать ее в новую, пустую базу данных. Это операция без потерь, но гарантирует, что все данные импортируются последовательно.

!!! tip
    Если дополнение предлагает тревожное количество удалений, сначала проверьте верхнюю полосу: она указывает на семейное дерево на сервере, в которое вы собираетесь записать. Синхронизация с сервером, который содержит *другое* дерево, приводит к именно такому симптому.

### Ошибки таймаута

Синхронизация с сервером обрабатывается фоновым работником, поэтому длительные синхронизации не должны истекать по времени. Сервер без настроенной очереди задач отклоняется на этапе подключения по этой причине — смотрите [Требования к серверу](#server-requirements).

Запросы от дополнения к серверу истекают через 60 секунд без ответа, поэтому недоступный сервер сообщает об ошибке подключения, а не зависает бесконечно.

### Неожиданные ошибки медиафайлов

Если загрузка медиафайла завершается неудачей, это часто вызвано несоответствием контрольной суммы фактического файла на диске и контрольной суммы в локальной базе данных Gramps. Это часто происходит с редактируемыми файлами, такими как офисные документы, отредактированными вне Gramps. Пожалуйста, используйте дополнение Gramps Media Verify, чтобы исправить контрольные суммы всех медиафайлов.

### Попросить о помощи

Если все вышеперечисленное не помогает, вы можете обратиться за помощью к сообществу, разместив сообщение в [категории Gramps Web форума Gramps](https://gramps.discourse.group/c/gramps-web/28). Пожалуйста, убедитесь, что вы предоставили:

- версию дополнения Gramps Web Sync (и используйте, пожалуйста, последнюю выпущенную версию) — она отображается внизу окна синхронизации, рядом с версией веб-API сервера
- версию настольного Gramps, которую вы используете
- вывод отладочной записи Gramps, включенной, как описано выше
- информацию о версии Gramps Web (вы можете найти ее в разделе Настройки/Информация о версии)
- любые детали, которые вы можете предоставить о вашей установке Gramps Web (самостоятельный хостинг, Grampshub и т.д.)
- вывод логов вашего сервера Gramps Web, если у вас есть к ним доступ (при использовании docker: `docker compose logs --tail 100 grampsweb` и `docker compose logs --tail 100 grampsweb-celery`)

## Фон: как работает дополнение

Если вам интересно, как на самом деле работает дополнение, вы можете найти некоторые дополнительные детали в этом разделе.

Дополнение предназначено для поддержания локальной базы данных Gramps в синхронизации с удаленной базой данных Gramps Web, чтобы позволить как локальные, так и удаленные изменения (коллаборативное редактирование).

Оно **не подходит**

- Для синхронизации с базой данных, которая не является прямым производным (начиная с копии базы данных или экспорта/импорта Gramps XML) локальной базы данных
- Для слияния двух баз данных с большим количеством изменений с обеих сторон, требующих ручного внимания для слияния. Для этой цели используйте отличный [Инструмент импорта слияния](https://www.gramps-project.org/wiki/index.php/Import_Merge_Tool).

Принципы работы инструмента очень просты:

- Он сравнивает локальные и удаленные базы данных
- Если есть какие-либо различия, он проверяет временную метку последнего идентичного объекта, давайте назовем его **t**
- Если объект изменился более недавно, чем **t**, существует в одной базе данных, но не в другой, он синхронизируется в обе (предполагается новый объект)
- Если объект изменился в последний раз до **t** и отсутствует в одной базе данных, он удаляется в обеих (предполагается удаленный объект)
- Если объект отличается, но изменился после **t** только в одной базе данных, синхронизируется в другую (предполагается измененный объект)
- Если объект отличается, но изменился после **t** в обеих базах данных, они объединяются (предполагается конфликтующее изменение)

Время последней успешной синхронизации также записывается, отдельно для каждого сервера, и используется как **t**, когда оно более актуально, чем самый новый идентичный объект.

Этот алгоритм прост и надежен, так как не требует отслеживания истории синхронизации. Однако он работает лучше всего, когда вы *синхронизируете часто*.
