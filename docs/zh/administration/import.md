# 导入数据

您可以通过上传从其他家谱程序、在线服务或 Gramps Desktop 导出的文件，将现有的家谱导入 Gramps Web。

导入有其专属页面，供树的拥有者和管理员使用。您可以通过 [管理设置](settings.md) 中的 **数据** 部分的 **导入家谱** 打开它（应用程序顶部工具栏中的用户图标 ▸ 管理）。当树仍然为空时，主页、家谱和列表中的“开始使用”卡片的 **导入家谱** 按钮也会引导您到此页面。

## 使用哪个文件

| 来源 | 将您的树导出为 | 文件扩展名 |
|---|---|---|
| 其他家谱程序或在线服务 | GEDCOM | `.ged` |
| Gramps Desktop | Gramps XML | `.gramps` |
| GeneWeb | GeneWeb | `.gw` |
| Pro-Gen | Pro-Gen | `.def` |
| 电子表格 | Gramps CSV | `.csv` |
| 地址簿 | vCard | `.vcf` |

GEDCOM 是几乎所有家谱程序和在线服务都可以导出的通用交换格式。在您的程序或网站中寻找“导出”或“下载”选项，如果提供多种格式，请选择 GEDCOM。Gramps Wiki 页面 [从其他家谱程序导入](https://www.gramps-project.org/wiki/index.php/Import_from_another_genealogy_program) 有关于特定程序的说明。

如果您使用 Gramps Desktop，请选择 Gramps XML (`.gramps`)，而不是 GEDCOM。它可以无损地携带所有 Gramps 数据，并且您的在线和离线树保持相同的标识符，因此可以进行 [同步](sync.md)。请参见下面的 [来自 Gramps Desktop](#coming-from-gramps-desktop)。

## 导入家谱文件

1. 按照上述说明打开导入页面。
2. 在“导入家谱”下，选择您的文件并点击 **导入**。上传进度将显示。
3. 文件首先被读取，随后会弹出“确认导入”对话框，显示它包含多少个对象（人员、家庭、事件、地点等），以及导入者的 [报告](#the-import-report)（如果有的话）。此时尚未向您的树中添加任何内容。检查计数是否合理，然后点击 **导入** 继续，或点击 **取消** 中止而不更改任何内容。如果您的树中已经包含人员，弹出对话框会警告您再次导入相同数据会创建重复项。
4. 导入在后台运行，并显示进度指示器。一旦数据导入完成，搜索索引将更新，这对于大型树可能需要一些时间。如果导入失败，将显示原因。
5. 如果树中尚无家庭成员，您将被提示选择一个。

导入完成后，检查结果：将主页 **统计** 面板中的人员数量与您旧程序中的数量进行比较，并打开您熟悉的一个家庭，以查看父母、子女、日期和地点是否如预期那样传递过来。如果文件引用了照片或其他媒体文件，请接下来在同一页面的 [导入媒体文件](import-media.md) 下添加它们。

!!! warning
    常规导入是纯粹的附加操作：它总是创建新对象，而从不更新或删除现有对象，即使这些对象在您的树中已经存在且具有相同的 Gramps ID 或句柄。重复导入相同文件或导入与树中已有数据重叠的文件将导致每个匹配对象重复，而不是合并或跳过它。

    如果您需要将其他地方的更改带入已导入的树，请使用 [从备份恢复](backups.md#restore-from-backup)，这将替换树以匹配上传的文件，而不是向其添加内容。这需要一个 Gramps XML 文件或 Gramps Web 备份。

## 导入报告

导入者报告他们无法完全导入的内容，例如他们无法理解的 GEDCOM 行、缺失的记录引用或过时的文件格式。报告在确认对话框和导入后都显示在 **报告** 下。在确认之前请阅读它：它通常解释了您在树中可能稍后才会注意到的问题。

并非每条消息都是问题——许多 GEDCOM 文件包含程序特定的数据，这些数据会被报告但保留，见 [程序特定数据](#program-specific-data)。使用报告旁边的按钮复制或下载为文本文件，例如以便在 [论坛](../help/help.md) 中请求帮助。

## 使用配额

服务器管理员可以为您的树设置限制（见 [服务器配置](../install_setup/configuration.md)）。**数据** 部分的顶部显示相对于这些限制的当前使用情况：

- **人员** – 树中人员对象的数量与配置的最大值（如果无限则为 ∞）
- **媒体存储** – 上传的媒体文件的总大小与配置的存储配额（如果无限则为 ∞）

任何会超过人员数量限制的导入将被整体拒绝。

## GEDCOM 文件

GEDCOM 5.5.1 和 GEDCOM 7 文件均可导入。需要注意一些事项。

### 字符编码

GEDCOM 5.5.1 文件在其头部声明其字符编码。支持 UTF-8、UTF-16、ANSEL 和 Windows（ANSI）编码。如果导入后带有重音或其他特殊字符的名称看起来乱码（例如 `MÃ¼ller` 而不是 `Müller`），则文件可能是使用与其声明不同的编码导出的。请从您的旧程序中重新导出文件，如果提供选择，请选择 UTF-8，并 [重新开始](#starting-over)。

GEDCOM 7 文件必须始终编码为 UTF-8；其他文件将被拒绝，并显示“无效的 GEDCOM 文件”错误。

### 程序特定数据

许多程序向 GEDCOM 添加自己的扩展，其他程序无法理解。Gramps 不会默默丢弃这些数据：它无法解释的行会被收集在附加到其所属的人员、家庭或其他对象的“GEDCOM 导入”类型的注释中。请查看这些注释，以查看是否有任何重要内容未能传递过来。

### 媒体文件

GEDCOM 文件包含对媒体文件（例如照片或扫描文档）的引用，但不包含文件本身。导入后，媒体对象在您的树中存在，但其文件缺失，这在 [媒体文件状态](import-media.md#media-file-status) 中显示。要添加文件，请参见 [导入媒体文件](import-media.md)。

## 来自 Gramps Desktop

如果您正在使用 Gramps Desktop，有两个步骤可以准备您的数据库，以确保接下来的操作顺利进行。

1. 检查并修复数据库
    - 可选：通过导出为 Gramps XML 创建数据库备份
    - 运行 [检查和修复数据库工具](https://gramps-project.org/wiki/index.php/Gramps_5.2_Wiki_Manual_-_Tools#Check_and_Repair_Database)。这修复一些可能导致 Gramps Web 问题的内部不一致性。
2. 将媒体路径转换为相对路径
    - 使用 Gramps 媒体管理器 [将所有媒体路径从绝对路径转换为相对路径](https://gramps-project.org/wiki/index.php/Gramps_5.2_Wiki_Manual_-_Tools#Convert_paths_from_relative_to_absolute)。请注意，即使使用相对路径，任何位于 Gramps 媒体目录之外的媒体文件在与 Gramps Web 同步时也无法正常工作。

然后将您的树导出为 Gramps XML (`.gramps`)，按照上述说明导入，并 [上传您的媒体文件](import-media.md)。要在计算机和网络上继续处理同一棵树，请使用 [Gramps Web 同步插件](sync.md)。

### 为什么不支持 Gramps XML 包？

虽然 Gramps XML (`.gramps`) 是导入数据的首选格式，但 Gramps XML *包* (`.gpkg`) 不被 Gramps Web 支持。这是因为媒体文件的导入和导出例程不适合在 Web 服务器上使用。

## 常见问题

**“不支持的格式”。** 仅列出的文件扩展名 [上面](#which-file-to-use) 可以导入。如果您的程序或在线服务给您一个 ZIP 压缩包，请解压并上传其中的 `.ged` 文件。

**所有内容都出现两次。** 相同的文件被导入了两次。由于导入从不合并，请 [重新开始](#starting-over)。

**特殊字符乱码。** 请参见 [字符编码](#character-encoding)。

**照片缺失。** 请参见 [导入媒体文件](import-media.md)。

### 重新开始

如果导入出现问题，或者您想在旧程序中修复某些内容并重新导入，请首先使用 [删除所有对象](#delete-all-objects) 清空树，然后导入修正后的文件。请注意，这也会删除您自导入以来在 Gramps Web 中所做的任何更改。

### 删除所有对象

!!! danger
    删除对象是 **不可逆的**。在继续之前请进行 [备份](backups.md)。

**删除所有对象** 位于 [管理设置](settings.md) 的 **危险区域** 部分。点击 **删除** 会打开一个对话框，您可以选择删除：

- **所有对象** – 完全清空树
- **特定对象类型** – 例如，仅事件或仅媒体对象

您将被要求重新验证（再次登录）以确认该操作。删除操作作为后台任务运行，并显示进度指示器。

!!! warning
    仅删除部分对象类型（而不是一次性删除所有对象）对于大型树可能需要很长时间，因为服务器必须检查和更新对象之间的所有关系。
