# 同步 Gramps Web 和 Gramps Desktop

*Gramps Web Sync* 是 Gramps 的一个插件，允许您将桌面计算机上的 Gramps 数据库与 Gramps Web 同步，包括媒体文件。

!!! warning
    与任何同步工具一样，请不要将其视为备份工具。一侧的意外删除将传播到另一侧。确保定期创建您家谱的备份（以 Gramps XML 格式）。

!!! info
    文档参考的是最新版本的 Gramps Web Sync 插件。如果需要，请使用 Gramps 插件管理器将插件更新到最新版本。

!!! note "1.5 版本的变化"
    插件的界面在 1.5 版本中进行了重写。逐步向导已被替换为一个窗口，媒体文件现在与对象更改一起确认，而不是在之后的单独页面上确认。如果您在寻找同步模式选择器，它现在位于更改列表的 **上方** 而不是下方。**合并**同步模式已被移除；请参见下面的 [同步模式](#sync-mode)。

## 安装

该插件需要运行在 Python 3.10 或更高版本上的 Gramps 6.0。
它可以在 Gramps Desktop 中使用，并可以 [以通常的方式安装](https://www.gramps-project.org/wiki/index.php/5.2_Addons#Installing_Addons_in_Gramps)。

!!! warning
    请确保在桌面上使用与服务器上运行的 Gramps 相同的版本。有关如何查找服务器上运行的 Gramps 版本，请参见 [获取帮助](../help/help.md) 部分。Gramps 版本的格式为 `MAJOR.MINOR.PATCH`，并且 Web 和桌面上的 `MAJOR` 和 `MINOR` 必须相同。

### 服务器要求

插件在连接时会检查服务器的两个方面，如果不满足其中任何一个，则拒绝继续。这两个检查在下载任何内容之前进行。

- **Gramps Web API 版本 3.x。** 该插件的版本适用于 Gramps 6.0，支持 Gramps Web API 3。较旧的服务器需要更新；运行 *更新* API 主版本的服务器需要更新的 Gramps，而不是更新的插件，因为每个 Gramps 发布版本与一个 API 版本配对。您可以在 Gramps Web 的 *设置 ▸ 版本信息* 中找到服务器的版本。
- **一个后台任务队列。** 同步将其更改作为后台任务提交。在未配置任务队列的服务器上，应用更改将同步运行，并在任何真实的家谱上超时，因此插件拒绝启动，而不是中途失败。

您还需要一个至少具有编辑权限的帐户才能对远程数据库应用更改。

可选步骤：

??? note inline end "Gnome 密钥环错误"
    目前在 python keyring 中存在一个 [错误](https://github.com/jaraco/keyring/issues/496)，影响许多 Gnome 桌面配置。您可能需要创建配置文件 `~/.config/python_keyring/keyringrc.cfg` 并将其编辑为如下所示：

        [backend]
        default-keyring=keyring.backends.SecretService.Keyring

- 安装 `keyring`（例如 `sudo apt install python3-keyring` 或 `sudo dnf install python3-keyring`），以便安全地将 API 密码存储在系统的密码管理器中。

如果无法使用密钥环，插件会提示并继续进行 — 您每次都会被要求输入密码。在 Gramps **Snap** 包中，系统密钥环因限制而被阻止，直到您连接一次接口：

```bash
snap connect gramps:password-manager-service
```

当插件检测到这种情况时，会显示此确切命令。

## 使用

安装后，插件可以在 Gramps 的 *工具 ▸ 家谱处理 ▸ Gramps&nbsp;Web&nbsp;Sync* 中使用。在确认对话框警告将丢弃撤消历史记录后，同步窗口打开。

**在您明确确认之前，不会对本地树或服务器应用任何更改。**

窗口顶部有一条条带，命名您正在同步的家谱、其所属的帐户和地址，以及上次同步的时间。在底部，显示插件和服务器 Web API 的版本 — 在报告问题时很有用。

### 连接

如果您之前已同步过此家谱并且密码已存储，插件将在打开时立即连接并直接进行比较。否则，它会询问您的 Gramps Web 实例的基本 URL（示例：`https://mygrampsweb.com/`）、您的用户名和密码。

URL 和用户名以明文存储在您的 Gramps 用户目录中。密码仅在您勾选 **记住密码** 时存储在系统密码管理器中；取消勾选会删除已为该服务器存储的任何密码。

!!! tip "多个家谱，多个服务器"
    每个您同步的服务器都是单独存储的，并记录其上次同步的时间。交替使用两个服务器不再干扰任何一方。

    每个条目还记录 **最后从哪个本地家谱** 同步。插件仅在与您打开的树匹配时自动连接；否则，它会显示连接详细信息并等待您按 *连接*，如果存储的凭据属于不同的树，则会发出警告。这很重要，因为将树与持有 *不同* 树的服务器同步会提议删除两个树的内容。

在没有任何内容被写入时，可以执行两个操作：

- **更改服务器…**，在顶部条带上，返回连接详细信息，以便您可以将此树指向不同的服务器。它会中断正在进行的比较，而不是让您等待完成。
- **忘记此服务器**，在连接面板上，删除存储的地址、用户名和密码，以及此树上次同步的记录。下次同步将从头开始比较两个树。

如果您输入的地址以 `http://` 开头而不是 `https://`，在您输入时会出现警告。您的密码将以明文发送，因此仅在本地测试时使用。

### 审查更改

插件比较本地和远程数据库，并显示它所提议的操作。与早期版本不同，早期版本列出了两个树之间的原始差异，现在列表显示将要执行的 **操作**，按更改的数据库分组：

```
▾ 将在此计算机上更改 (7 个对象)
    ▾ 添加 3 个对象
        人物   约翰·史密斯        I0123
    ▾ 更新 4 个对象
        …
▾ 将在服务器上更改 (5 个对象)
    …
```

每一行都命名对象，因此您可以知道谁或什么受到影响，而不仅仅是看到 Gramps ID。

如果有任何内容将被删除，列表上方的警告会说明有多少对象以及在哪一侧。这在涉及删除时会出现，包括在普通的双向同步中传播您自己所做的删除。

按 **应用** 以执行列表所描述的操作。

!!! warning "审查时请勿编辑"
    同步窗口不会阻止 Gramps 的其余部分，因此您可以在列表打开时继续工作。如果您编辑了受影响的对象，插件会在您按应用时检测到，停止而不更改任何内容，并要求您再次比较。没有任何内容丢失，但必须重复比较。

#### 同步模式

同步模式在更改列表的 **上方** 选择。更改它会重建列表，因为模式决定每个差异实际上变成什么。

- **双向同步**（默认） — 双方的更改被合并。两个地方编辑的对象会被合并。
- **重置服务器以匹配此计算机** — 服务器将与此计算机匹配。仅在服务器上更改的任何内容将被丢弃。
- **重置此计算机以匹配服务器** — 此计算机将与服务器匹配。仅在此处更改的任何内容将被丢弃。

!!! note
    早期版本中可用的 **合并** 模式已被移除。它与双向同步的不同之处在于恢复一侧删除的对象，而不是传播删除，这不是界面可以有效解释的区别。如果您依赖于它，请使用双向同步并从备份中恢复您想要保留的任何内容。

### 媒体文件

媒体文件作为同一确认的一部分处理，而不是作为单独的步骤。如果需要传输任何文件，列表下方的复选框提供移动它们的选项：

```
[x] 还转移 12 个媒体文件（4 个下载，8 个上传）
```

取消勾选以同步对象更改而不触及文件。

在 *两个* 侧面都缺失的文件会单独列出，因为无法对其进行任何操作：

```
2 个媒体文件在两个侧面都缺失，无法转移。
```

请注意媒体文件同步的以下限制：

- 如果本地文件的校验和与存储在 Gramps 数据库中的校验和不同（例如，对于在添加到 Gramps 后编辑的 Word 文件），则上传将失败并显示错误消息。
- 工具不会检查所有本地文件的完整性，因此如果本地文件存在于存储的媒体对象路径下，但文件与服务器上的文件不同，工具将无法检测到。请使用媒体验证插件检测校验和不正确的文件。

### 当出现问题时

如果同步在中途失败 — 例如，连接中断 — 插件会报告它已经应用的内容，并提供 **重试**，这将从失败的步骤恢复，而不是重新开始。下载的远程树副本将被保留，因此重试不会再次下载和比较它。

故障的技术细节可以在 *详细信息* 展开器后面找到，并有一个按钮可以复制它们以进行错误报告。

## 故障排除

### 调试日志

如果您在使用同步插件时遇到问题，请通过 [从命令行启动 Gramps](https://gramps-project.org/wiki/index.php/Gramps_5.2_Wiki_Manual_-_Command_Line) 启动 Gramps，并启用调试日志，使用以下选项：

```bash
gramps --debug grampswebsync
```

这将在命令行中打印许多有助于您识别问题原因的日志语句。

### 服务器凭据

如果连接失败，请仔细检查服务器 URL、您的用户名和密码。

### 插件拒绝连接

如果插件报告服务器的 Gramps Web API 版本过旧或过新，或者未配置后台任务队列，请参见上面的 [服务器要求](#server-requirements)。这些在其他任何检查之前进行，因此消息直接指出问题。

### 权限问题

如果您遇到与权限相关的错误，请检查您的 Gramps Web 用户帐户的用户角色。只有在您是具有编辑、所有者或管理员角色的用户时，才能对远程数据库应用更改。

### 意外的数据库更改

如果同步工具检测到您认为没有发生的更改，可能是因为其中一个数据库存在不一致，导致 Gramps 检测到差异，或者您的本地计算机与服务器之间的时间不同步。

请检查两台机器的时钟是否正确设置（注意，时区无关紧要，因为该工具使用 Unix 时间戳，时间戳与时区无关）。

您还可以在本地数据库上运行检查和修复工具，看看这是否有帮助。

确保本地数据库中的不一致不会导致误报的一个粗暴但有效的方法是将数据库导出为 Gramps XML 并重新导入到一个新的空数据库中。这是一个无损操作，但确保所有数据一致导入。

!!! tip
    如果插件提议的删除数量令人震惊，请先检查顶部条带：它命名您即将写入的服务器上的家谱。与持有 *不同* 树的服务器同步会产生完全相同的症状。

### 超时错误

对服务器的同步由后台工作者处理，因此长时间运行的同步不应超时。未配置任务队列的服务器在连接时会被拒绝，原因如上所述 — 请参见 [服务器要求](#server-requirements)。

来自插件对服务器的请求在 60 秒内没有响应会超时，因此无法访问的服务器会报告连接错误，而不是无限期挂起。

### 意外的媒体文件错误

如果上传媒体文件失败，通常是由于磁盘上实际文件的校验和与本地 Gramps 数据库中的校验和不匹配。这通常发生在外部编辑的可编辑文件（如办公文档）上。请使用 Gramps 媒体验证插件来纠正所有媒体文件的校验和。

### 寻求帮助

如果以上所有方法都没有帮助，您可以通过在 [Gramps 论坛的 Gramps Web 类别](https://gramps.discourse.group/c/gramps-web/28) 中发帖向社区寻求帮助。请确保提供：

- Gramps Web Sync 插件的版本（请使用最新发布的版本） — 它显示在同步窗口的底部，位于服务器的 Web API 版本旁边
- 您正在使用的 Gramps Desktop 版本
- 按上述说明启用的 Gramps 调试日志的输出
- Gramps Web 的版本信息（您可以在设置/版本信息中找到）
- 关于您的 Gramps Web 安装的任何详细信息（自托管、Grampshub 等）
- 如果您可以访问 Gramps Web 服务器日志，请提供其输出（使用 docker 时：`docker compose logs --tail 100 grampsweb` 和 `docker compose logs --tail 100 grampsweb-celery`）

## 背景：插件的工作原理

如果您对插件的实际工作原理感到好奇，可以在本节中找到更多细节。

该插件旨在保持本地 Gramps 数据库与远程 Gramps Web 数据库同步，以允许本地和远程更改（协作编辑）。

它 **不适合**

- 与不是本地数据库直接派生（从数据库副本或 Gramps XML 导出/导入） 的数据库同步
- 合并两个在两侧都有大量更改需要手动处理的数据库。请使用优秀的 [导入合并工具](https://www.gramps-project.org/wiki/index.php/Import_Merge_Tool) 来实现这一目的。

该工具的操作原则非常简单：

- 它比较本地和远程数据库
- 如果有任何差异，它会检查最新相同对象的时间戳，称为 **t**
- 如果在一个数据库中存在比 **t** 更新更近的对象，但在另一个数据库中不存在，则将其同步到两个数据库（假设为新对象）
- 如果在 **t** 之前的最后一次更改的对象在一个数据库中缺失，则在两个数据库中删除（假设为已删除对象）
- 如果对象不同但在 **t** 之后仅在一个数据库中更改，则同步到另一个数据库（假设为已修改对象）
- 如果对象不同但在两个数据库中都在 **t** 之后更改，则合并它们（假设为冲突修改）

最后一次成功同步的时间也会被记录，分别针对每个服务器，并在其比最新相同对象更新时用作 **t**。

该算法简单且稳健，因为它不需要跟踪同步历史记录。然而，它在您 *经常同步* 时效果最佳。
