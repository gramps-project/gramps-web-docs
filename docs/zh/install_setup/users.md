# 用户系统

Gramps Web 并不打算向公众开放互联网访问，而仅限于经过身份验证的用户。用户帐户可以通过命令行或网页界面由站点所有者创建，或者通过自我注册并随后由站点所有者批准。

## 用户角色

当前定义了以下用户角色。

角色 | 角色 ID | 权限
-----|---------|------------
访客 | 0 | 查看非私密对象
成员 | 1 | 访客 + 查看私密对象
贡献者* | 2 | 成员 + 添加对象
编辑 | 3 | 贡献者 + 编辑和删除对象
所有者 | 4 | 编辑 + 管理用户
管理员 | 5 | 所有者 + 在多树设置中编辑其他树

记录是否为私密记录是按记录设置的，详见 [私密记录](../user-guide/privacy.md)。默认情况下，没有任何内容是私密的，甚至包括活着的人。

\* 请注意，“贡献者”角色目前仅部分支持；例如，家庭对象无法添加，因为它们意味着对家庭成员的基础 Gramps 人物对象的修改。建议在可能的情况下使用其他角色。

## 管理用户

有两种方式来管理用户：

- 使用网页界面并拥有所有者权限
- 在服务器的命令行上

需要首先访问网页应用程序的所有者帐户可以在访问 Gramps Web 时自动启动的入职向导中添加，该向导在用户数据库为空时启动。

### 在命令行上管理用户

使用 [Docker Compose](deployment.md) 时，基本命令是

```bash
docker compose run grampsweb python3 -m gramps_webapi user COMMAND [ARGS]
```

`COMMAND` 可以是 `add`、`set-password` 或 `delete`。使用 `--help` 获取 `[ARGS]` 的语法和可能的配置选项。

`set-password NAME` 为现有用户设置新密码，而无需旧密码，例如当没有人能够再登录且未设置电子邮件以进行密码重置时（Gramps Web API 3.26+）。它会要求输入两次密码而不显示，因此密码不会出现在 shell 历史记录中。所有用户的会话都会结束。

### 批准自我注册的用户

当用户自我注册时，他们不会立即获得访问权限。会向树的所有者发送一封关于新用户注册的电子邮件，并向用户发送一封电子邮件请求以确认他们的电子邮件地址。成功确认电子邮件地址后，他们的角色将从 `unconfirmed` 更改为 `disabled`。在这两种角色中的任何一种下，用户都无法登录。树的所有者必须审核用户的请求并为用户分配适当的角色，然后他们才能登录。
