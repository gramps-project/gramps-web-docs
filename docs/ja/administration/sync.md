# Gramps Web と Gramps Desktop の同期

*Gramps Web Sync* は、デスクトップコンピュータ上の Gramps データベースと Gramps Web を同期させるためのアドオンで、メディアファイルも含まれます。

!!! warning
    すべての同期ツールと同様に、これをバックアップツールと考えないでください。一方での偶発的な削除は、もう一方に伝播します。家系図の定期的なバックアップ（Gramps XML 形式）を作成することを確認してください。

!!! info
    ドキュメントは、Gramps Web Sync アドオンの最新バージョンを参照しています。必要に応じて、Gramps アドオンマネージャーを使用してアドオンを最新バージョンに更新してください。

!!! note "バージョン 1.5 の変更点"
    アドオンのインターフェースは、バージョン 1.5 で書き直されました。ステップバイステップウィザードは廃止され、単一のウィンドウに置き換えられ、メディアファイルはオブジェクトの変更と一緒に確認されるようになりました。同期モードセレクターは、今では変更リストの**上部**に配置されています。**マージ**同期モードは削除されました。以下の [Sync mode](#sync-mode) を参照してください。

## インストール

このアドオンは、Python 3.10 以上で動作する Gramps 6.0 を必要とします。Gramps Desktop で利用可能で、[通常の方法](https://www.gramps-project.org/wiki/index.php/5.2_Addons#Installing_Addons_in_Gramps) でインストールできます。

!!! warning
    デスクトップの Gramps のバージョンが、サーバーで実行されているものと同じであることを確認してください。サーバーが実行している Gramps のバージョンを確認する方法については、[Get Help](../help/help.md) セクションを参照してください。Gramps のバージョンは `MAJOR.MINOR.PATCH` の形式で、`MAJOR` と `MINOR` はウェブとデスクトップで同じでなければなりません。

### サーバー要件

アドオンは接続するとすぐにサーバーについて2つのことをチェックし、どちらかが満たされない場合は続行を拒否します。両方のチェックは、何かがダウンロードされる前に行われます。

- **Gramps Web API バージョン 3.x.** このアドオンのバージョンは、Gramps 6.0 用で、Gramps Web API 3 と互換性があります。古いサーバーは更新が必要です。*新しい* API メジャーバージョンで実行されているサーバーは、アドオンではなく新しいバージョンの Gramps が必要です。各 Gramps リリースラインは、1 つの API バージョンとペアになっています。サーバーのバージョンは、Gramps Web の *Settings ▸ Version info* で確認できます。
- **バックグラウンドタスクキュー。** 同期は、変更をバックグラウンドタスクとして提出します。タスクキューが構成されていないサーバーでは、変更を適用することが同期的に実行され、実際の家系図ではタイムアウトするため、アドオンは途中で失敗するのではなく、開始を拒否します。

リモートデータベースに変更を適用するには、少なくともエディタ権限を持つアカウントが必要です。

オプションのステップ：

??? note inline end "Gnome keyring bug"
    現在、[python keyring のバグ](https://github.com/jaraco/keyring/issues/496) が多くの Gnome デスクトップ構成に影響を与えています。設定ファイル `~/.config/python_keyring/keyringrc.cfg` を作成し、次のように編集する必要があるかもしれません：

        [backend]
        default-keyring=keyring.backends.SecretService.Keyring

- `keyring` をインストールします（例： `sudo apt install python3-keyring` または `sudo dnf install python3-keyring`） これにより、API パスワードをシステムのパスワードマネージャーに安全に保存できます。

キーレリングが使用できない場合、アドオンはその旨を通知し、キーレリングなしで続行します — その場合、毎回パスワードを求められます。Gramps **Snap** パッケージでは、システムキーレリングは、インターフェースを一度接続するまで制限されます：

```bash
snap connect gramps:password-manager-service
```

アドオンは、この状況を検出したときにこの正確なコマンドを表示します。

## 使用法

インストールが完了すると、アドオンは Gramps の *Tools ▸ Family Tree Processing ▸ Gramps&nbsp;Web&nbsp;Sync* に表示されます。元に戻す履歴が破棄されるという警告ダイアログを確認すると、同期ウィンドウが開きます。

**明示的に確認するまで、ローカルツリーやサーバーに変更は適用されません。**

ウィンドウの上部には、同期している家系図の名前、所属するアカウントとアドレス、最後に同期された日時が表示されます。下部には、アドオンとサーバーの Web API のバージョンが表示されます — 問題を報告する際に便利です。

### 接続

この家系図を以前に同期したことがあり、パスワードが保存されている場合、アドオンは開くとすぐに接続し、比較に進みます。そうでない場合は、Gramps Web インスタンスのベース URL（例： `https://mygrampsweb.com/`）、ユーザー名、およびパスワードを求められます。

URL とユーザー名は、Gramps ユーザーディレクトリにプレーンテキストで保存されます。**パスワードを記憶する** にチェックを入れた場合のみ、パスワードはシステムのパスワードマネージャーに保存されます。チェックを外すと、そのサーバーに対して既に保存されているパスワードは削除されます。

!!! tip "複数の家系図、複数のサーバー"
    同期する各サーバーは別々に保存され、最後に同期された日時の記録も保持されます。2つのサーバーを交互に使用しても、どちらにも影響はありません。

    各エントリは、**どのローカル家系図**から最後に同期されたかも記録します。アドオンは、そのツリーが開いているときのみ自動的に接続します。そうでない場合は、接続の詳細を表示し、*Connect* を押すのを待ちます。保存された資格情報が異なるツリーに属している場合は警告が表示されます。これは、異なるツリーを持つサーバーに対してツリーを同期すると、両方の内容を削除する提案がされるため、重要です。

何も書き込まれていない間に利用可能な2つのアクションがあります：

- **サーバーを変更…**、上部のストリップで、接続の詳細に戻り、このツリーを別のサーバーに向けることができます。進行中の比較を中断することなく、完了を待つ必要はありません。
- **このサーバーを忘れる**、接続ペインで、保存されたアドレス、ユーザー名、パスワード、およびこのツリーが最後に同期された日時の記録を削除します。次回の同期では、2つのツリーを最初から比較します。

`http://` で始まるアドレスを入力すると、入力中に警告が表示されます。パスワードは平文で送信されるため、ローカルテストのみに使用してください。

### 変更の確認

アドオンはローカルデータベースとリモートデータベースを比較し、何を行うかを提案します。以前のバージョンとは異なり、2つのツリー間の生の違いをリストするのではなく、リストにはどのデータベースが変更されるかに基づいてグループ化された**アクション**が表示されます：

```
▾ このコンピュータで変更される予定 (7 オブジェクト)
    ▾ 3 オブジェクトを追加
        人物   ジョン・スミス        I0123
    ▾ 4 オブジェクトを更新
        …
▾ サーバーで変更される予定 (5 オブジェクト)
    …
```

各行にはオブジェクトの名前が付けられているため、Gramps ID だけでなく、誰または何が影響を受けるかを知ることができます。

何かが削除される場合、リストの上部に、どれだけのオブジェクトがどちら側で削除されるかを示す警告が表示されます。これは、あなた自身が行った削除を伝播する通常の双方向同期中にも表示されます。

**Apply** を押して、リストに記載されている内容を実行します。

!!! warning "確認中に編集しないでください"
    同期ウィンドウは Gramps の残りの部分をブロックしないため、リストが開いている間も作業を続けることができます。影響を受けるオブジェクトを編集した場合、アドオンは Apply を押したときにそれを検出し、何も変更せずに停止し、再度比較するように求めます。何も失われることはありませんが、比較は繰り返す必要があります。

#### 同期モード

同期モードは、変更リストの**上部**で選択されます。変更するとリストが再構築されます。なぜなら、モードが各違いが実際に何になるかを決定するからです。

- **双方向同期**（デフォルト） — 両側の変更が統合されます。両方の場所で編集されたオブジェクトはマージされます。
- **このコンピュータに合わせてサーバーをリセット** — サーバーがこのコンピュータに合わせて変更されます。サーバーでのみ変更されたものは破棄されます。
- **サーバーに合わせてこのコンピュータをリセット** — このコンピュータがサーバーに合わせて変更されます。ここでのみ変更されたものは破棄されます。

!!! note
    以前のバージョンで利用可能だった**マージ**モードは削除されました。これは、削除を伝播するのではなく、一方で削除されたオブジェクトを復元する点で双方向同期と異なっていましたが、インターフェースが有用に説明できる区別ではありませんでした。これに依存していた場合は、双方向同期を使用し、バックアップから保持したいものを復元してください。

### メディアファイル

メディアファイルは、別のステップではなく、同じ確認の一部として処理されます。転送が必要なファイルがある場合、リストの下にチェックボックスが表示され、ファイルを移動するオプションが提供されます：

```
[x] 12 メディアファイルも転送 (4 をダウンロード、8 をアップロード)
```

チェックを外すと、ファイルに触れずにオブジェクトの変更を同期します。

*両方*の側で欠落しているファイルは別にリストされます。なぜなら、それらに対しては何もできないからです：

```
両方の側で 2 メディアファイルが欠落しており、転送できません。
```

メディアファイルの同期に関する以下の制限に注意してください：

- ローカルファイルが Gramps データベースに保存されているものと異なるチェックサムを持っている場合（これは、Gramps に追加された後に編集された Word ファイルなどで発生する可能性があります）、アップロードはエラーメッセージと共に失敗します。
- ツールはすべてのローカルファイルの整合性をチェックしないため、メディアオブジェクトに保存されているパスの下にローカルファイルが存在しても、サーバー上のファイルと異なる場合、ツールはそれを検出しません。誤ったチェックサムを持つファイルを検出するには、Media Verify Addon を使用してください。

### 何かがうまくいかない場合

同期が途中で失敗した場合（たとえば、接続が切れた場合）、アドオンは既に適用した内容を報告し、**Try again** を提供します。これにより、失敗したステップから再開され、最初からやり直すことはありません。リモートツリーのダウンロードコピーは保持されるため、再試行しても再度ダウンロードして比較することはありません。

失敗の技術的詳細は、*Details* エクスパンダーの後ろにあり、バグレポート用にそれらをコピーするボタンがあります。

## トラブルシューティング

### デバッグログ

Sync Addon に問題が発生している場合は、次のオプションを使用して [コマンドラインから Gramps を起動](https://gramps-project.org/wiki/index.php/Gramps_5.2_Wiki_Manual_-_Command_Line) し、デバッグログを有効にしてください：

```bash
gramps --debug grampswebsync
```

これにより、問題の原因を特定するのに役立つ多くのログステートメントがコマンドラインに出力されます。

### サーバー資格情報

接続が失敗した場合は、サーバーの URL、ユーザー名、パスワードを再確認してください。

### アドオンが接続を拒否する

アドオンがサーバーの Gramps Web API バージョンが古すぎるか新しすぎる、またはバックグラウンドタスクキューが構成されていないと報告する場合は、上記の [Server requirements](#server-requirements) を参照してください。これらは他の何よりも先にチェックされるため、メッセージは問題を直接示します。

### 権限の問題

権限に関するエラーが発生した場合は、Gramps Web ユーザーアカウントのユーザーロールを確認してください。リモートデータベースに変更を適用できるのは、エディタ、オーナー、または管理者の役割を持つユーザーのみです。

### 予期しないデータベースの変更

同期ツールが発生していないと思われる変更を検出した場合、どちらかのデータベースに不整合があり、Gramps が違いを検出する原因になっているか、ローカルコンピュータとサーバー間の時間が同期していない可能性があります。

両方のマシンの時計が正しく設定されていることを確認してください（注意：タイムゾーンは問題ではありません。ツールは Unix タイムスタンプを使用しており、タイムゾーンに依存しません）。

ローカルデータベースでチェック＆修復ツールを実行し、これが役立つかどうかを確認することもできます。

ローカルデータベースの不整合が誤検知を引き起こしていないことを確認するための強引だが効果的な方法は、データベースを Gramps XML にエクスポートし、新しい空のデータベースに再インポートすることです。これはロスレス操作ですが、すべてのデータが一貫してインポートされることを保証します。

!!! tip
    アドオンが驚くべき数の削除を提案する場合は、まず上部のストリップを確認してください：それは、書き込もうとしているサーバー上の家系図の名前を示しています。*異なる* ツリーを持つサーバーに対して同期すると、まさにこの症状が発生します。

### タイムアウトエラー

サーバーへの同期はバックグラウンドワーカーによって処理されるため、長時間の同期はタイムアウトしないはずです。タスクキューが構成されていないサーバーは、この理由で接続時に拒否されます — [Server requirements](#server-requirements) を参照してください。

アドオンからサーバーへのリクエストは、60 秒間応答がない場合にタイムアウトするため、到達不能なサーバーは無限にハングするのではなく、接続エラーを報告します。

### 予期しないメディアファイルエラー

メディアファイルのアップロードが失敗する場合、これは実際のディスク上のファイルとローカル Gramps データベース内のチェックサムの不一致が原因であることが多いです。これは、Gramps の外で編集されたオフィス文書などの編集可能なファイルでよく発生します。すべてのメディアファイルのチェックサムを修正するには、Gramps Media Verify Addon を使用してください。

### ヘルプを求める

上記のすべてが役立たない場合は、[Gramps フォーラムの Gramps Web カテゴリ](https://gramps.discourse.group/c/gramps-web/28) に投稿してコミュニティに助けを求めることができます。以下の情報を提供することを確認してください：

- Gramps Web Sync アドオンのバージョン（最新のリリースバージョンを使用してください） — 同期ウィンドウの下部に、サーバーの Web API バージョンの隣に表示されます
- 使用している Gramps デスクトップのバージョン
- 上記のように有効にした Gramps デバッグログの出力
- Gramps Web のバージョン情報（Settings/Version info の下にあります）
- Gramps Web インストールに関する詳細（自己ホスト、Grampshub など）
- Gramps Web サーバーログの出力（アクセスできる場合）（docker を使用している場合： `docker compose logs --tail 100 grampsweb` および `docker compose logs --tail 100 grampsweb-celery`）

## 背景：アドオンの動作方法

アドオンが実際にどのように機能するかに興味がある場合は、このセクションでさらに詳細を見つけることができます。

アドオンは、ローカル Gramps データベースをリモート Gramps Web データベースと同期させ、ローカルとリモートの両方の変更（共同編集）を可能にすることを目的としています。

これは**適していません**

- ローカルデータベースの直接の派生物（データベースのコピーまたは Gramps XML エクスポート/インポートから開始）ではないデータベースとの同期
- 両側に多くの変更があり、手動でのマージが必要な2つのデータベースをマージすること。これには、優れた [Import Merge Tool](https://www.gramps-project.org/wiki/index.php/Import_Merge_Tool) を使用してください。

ツールの動作原理は非常にシンプルです：

- ローカルデータベースとリモートデータベースを比較します
- 違いがある場合、最新の同一オブジェクトのタイムスタンプをチェックします。これを**t**と呼びます
- **t** よりも最近に変更されたオブジェクトが一方のデータベースに存在し、もう一方には存在しない場合、それは両方に同期されます（新しいオブジェクトと仮定します）
- **t** よりも前に最後に変更されたオブジェクトが一方のデータベースに存在しない場合、それは両方で削除されます（削除されたオブジェクトと仮定します）
- オブジェクトが異なりますが、**t** の後に一方のデータベースでのみ変更された場合、もう一方に同期されます（変更されたオブジェクトと仮定します）
- オブジェクトが異なりますが、両方のデータベースで **t** の後に変更された場合、マージされます（競合する変更と仮定します）

最後の成功した同期の時間も記録され、各サーバーごとに別々に使用され、最新の同一オブジェクトよりも新しい場合は **t** として使用されます。

このアルゴリズムはシンプルで堅牢であり、同期履歴を追跡する必要がありません。ただし、*頻繁に同期する* 場合に最も効果的です。
