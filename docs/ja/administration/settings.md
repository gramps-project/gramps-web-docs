# 管理設定

**設定 > 管理** ページは、アプリの上部バーにあるユーザーアイコンからアクセスできます。このページは、オーナーまたは管理者の役割を持つユーザーのみが利用でき、家系図データベースを管理するためのツールを提供します。

ページは折りたたみ可能なセクションに整理されています。セクションのヘッダーをクリックすると展開されます。

## データ

使用量のクォータ、データのインポート、およびメディアファイルの管理をカバーします。

### 使用量のクォータ

セクションの上部には、設定された制限に対する現在の使用状況が表示されます：

- **人物** – ツリー内の人物オブジェクトの数と設定された最大数（無制限の場合は∞）
- **メディアストレージ** – アップロードされたメディアファイルの合計サイズと設定されたストレージクォータ（無制限の場合は∞）

クォータはサーバー管理者によって設定されます。詳細については、[サーバー設定](../install_setup/configuration.md)を参照してください。

### データのインポート

インポートセクションでは、家系図ファイルまたはメディアアーカイブをアップロードできます。完全な手順については、[データのインポート](import.md)を参照してください。

### メディアファイルのステータス

このセクションでは次のことが表示されます：

- ツリー内のメディアオブジェクトの総数と、チェックサムが欠けているものがあるかどうか
- サーバーから関連ファイルが欠けているメディアオブジェクトの数

緑のチェックマークはすべてが正常であることを示します。問題が検出された場合、影響を受けたオブジェクトへのリンクが表示されます。欠けているチェックサムは、メディアリファレンスは含まれているが実際のファイルは含まれていないGEDCOMなどの形式からデータがインポートされた場合に通常発生します。欠けているファイルは、メディアアーカイブのインポート機能を使用してアップロードできます。

### メディアアーカイブのインポート

欠けているファイルを補うために、メディアファイルのZIPファイルをアップロードできます。完全な手順については、[データのインポート](import.md)を参照してください。

## 検索インデックス

### 検索インデックスの管理

Gramps Webは、データが変更されるたびに通常自動的に更新されるフルテキスト検索インデックスを維持します。ステータスインジケーターは、現在インデックスされているオブジェクトの数と総オブジェクト数を示します。

**検索インデックスを更新**をクリックすると、完全な再構築がトリガーされます。タスクがバックグラウンドで実行されている間、進行状況インジケーターが表示されます。これは通常、サーバーのアップグレード後にのみ必要です。

### セマンティック検索インデックス

!!! warning "非推奨"
    セマンティック検索は非推奨であり、Gramps Web API 3.25でこのセクションと共に削除されます。AIチャットは、Gramps Web API 3.24では必要ありません。

サーバーに[セマンティック（AI駆動）検索が有効](../install_setup/chat.md#semantic-search-deprecated)になっている場合、追加のセクションが表示され、2つのアクションが含まれます：

- **セマンティック検索インデックスを再生成** – セマンティックインデックス全体を最初から再構築します。これは計算コストが高く、時間がかかる場合があります。
- **セマンティック検索インデックスを更新** – 増分更新を実行し、まだインデックスされていないオブジェクトのみを追加します。完全な再構築よりも速いです。

## ツリー設定

### 家系図名

!!! note
    ツリーの名前を変更することは、[マルチツリー設定](../install_setup/multi-tree.md)または[サーバー設定](../install_setup/configuration.md)で`TREE_ID`が明示的に設定されている場合にのみ機能します。`TREE_ID`が設定されていないデフォルトのシングルツリーインストールでは、エラーが発生します。

これにより、基盤となるGramps家系図データベースの名前を変更できます。新しい名前を入力し、**名前を変更**をクリックして適用します。

!!! tip
    データベースの名前を変更せずにアプリバーに表示される名前だけを変更したい場合は、代わりに[アプリタイトル](#app-title)設定を使用してください。

### 研究者情報

主要な研究者の名前、住所、および連絡先の詳細を設定します。この情報はエクスポート（例：GEDCOMファイル）に埋め込まれます。

## カスタマイズ

### テーマカラー

Gramps Webインターフェースのカスタム**プライマリーカラー**と**アクセントカラー**を設定します。これらの色は、このツリーのすべてのユーザーに適用され、保存後すぐに反映されます。

カラーピッカーを使用して色を選択し、次に**保存**をクリックします。**リセット**をクリックするとデフォルトに戻ります。

### アプリタイトル

アプリケーションのカスタムタイトルを設定します。設定されている場合、これはブラウザのタイトルバーと上部アプリバーの家系図名を上書きします。

タイトルを入力し、**保存**をクリックします。デフォルト（家系図名）を使用するには空白のままにします。

### ホームページノート

ダッシュボードのホームページに表示するGrampsの**ノート**オブジェクトを選択します。ノートの内容は、メインダッシュボードの列の下にレンダリングされ、ツリーにアクセスできるすべてのユーザーに表示されます。

オブジェクトセレクターを使用してノートを検索して選択し、次に保存します。**削除**をクリックして現在のホームページノートをクリアします。

### ホームページ画像

ダッシュボードのホームページに画像として表示するGrampsの**メディア**オブジェクトを選択します。ホームページノートと組み合わせると、画像はノートテキストの横に表示されます。ノートがない場合は、画像のみが表示されます。

オブジェクトセレクターを使用してメディアオブジェクトを検索して選択し、次に保存します。**削除**をクリックして現在のホームページ画像をクリアします。

### エクスポート/インポート設定

ツリーの設定（アプリタイトル、テーマカラー、ホームページノート/画像など）は、バックアップ用または別のGramps WebインスタンスにコピーするためにJSONファイルとしてエクスポートできます。

- **設定をエクスポート**をクリックして、現在の設定をJSONファイルとしてダウンロードします。
- **ツリー設定をインポート**をクリックして、以前にエクスポートされたJSONファイルをアップロードし、設定を適用します。

## 家系図処理

### データベースのチェックと修復

このツールは、Grampsデータベースの内部矛盾をチェックし、修正できるものを修正します - Gramps Desktopの[データベースのチェックと修復ツール](https://www.gramps-project.org/wiki/index.php/Gramps_5.2_Wiki_Manual_-_Tools#Check_and_Repair_Database)に類似しています。

**チェックと修復**をクリックし、進行状況インジケーターが完了するのを待ちます。結果はボタンの下に表示されます：

- エラーが見つからなかった場合、確認メッセージが表示されます。
- エラーが見つかった場合、適用された修正の概要が表示されます。

予期しないエラーや、オブジェクト間の関係が欠けているなどのデータベースの矛盾が原因である可能性のある動作に遭遇した場合は、このツールを実行してください。

### データの検証

[データベースのチェックと修復](#check-and-repair-database)が*技術的*な矛盾を探すのに対し、このツールは*信じがたい*データを探します - Gramps Desktopの[データの検証ツール](https://gramps-project.org/wiki/index.php/Gramps_5.0_Wiki_Manual_-_Tools#Verify_the_Data)に類似しています。母親が12歳である、または130歳まで生きた人など、あり得ないわけではないが再確認する価値がある事例を報告します。

**オプション**の下で、テストが使用するしきい値を調整できます - 最大年齢、結婚または子供を持つための最小および最大年齢、最大子供数など - また、欠けているまたは不正確な日付を推定するかどうか、31日のような無効な日付を報告するかどうかを設定できます。

**データを検証**をクリックして開始します。チェックはバックグラウンドタスクとして実行され、その後、**データ検証結果**の下に結果がリストされます。このツールによって何も変更されることはありません：それは見つけたものを報告するだけです。

!!! note
    発見はエラーの証明ではありません。長生きや大きな年齢差は実際に発生するため、結果を修正すべきもののリストではなく、確認すべきもののリストとして扱ってください。

## タグ

### タグの管理

家系図のための[タグ](../user-guide/tags.md)を作成、名前変更、色変更、削除します。タグはGrampsデータベースに保存され、すべてのユーザーで共有され、Gramps Desktopと完全に互換性があります。

**新しいタグ**をクリックしてタグを作成します。既存のタグの横にあるコントロールを使用して、名前を変更する（鉛筆アイコン）、色を変更する（カラーピッカー）、または削除する（削除アイコン）ことができます。

!!! note
    タグを削除すると、それが適用されていたすべてのオブジェクトから削除されます。

Gramps Web全体でタグがどのように使用されているか、特に特別な`Blog`および`ToDo`タグについては、[タグ](../user-guide/tags.md)を参照してください。

## バックアップ

バックアップには、家系図データ、プライベートレコード、ツリー設定、およびツリーのユーザーが含まれます。メディアファイルは含まれていません。メディアファイルのバックアップについては、[メディアファイルをバックアップする](export.md#back-up-your-media-files)を参照してください。

### 保存されたバックアップ

サーバー管理者がバックアップディレクトリ（`BACKUP_DIR`、[サーバー設定](../install_setup/configuration.md)を参照）を設定している場合、バックアップはサーバーに保存できます。そうでない場合、このセクションにはバックアップの保存が設定されていないという通知が表示され、アップロードされたファイルからの復元のみが利用可能です。

**バックアップを作成...**をクリックしてバックアップを作成します。バックグラウンドタスクとして作成され、その後、保存されたバックアップのリストに日付、人数、サイズと共に表示されます。サーバーは最新のバックアップ（デフォルトで5つ）しか保持せず、古いものは自動的に削除されます。1日に作成できるバックアップの数にも制限があります。

保存されたバックアップごとに、次のことができます：

- **ダウンロード** – 例えば、他の場所にコピーを保持するために`.tar`ファイルとしてダウンロードします。
- **復元** – 以下に説明するように復元します。
- **削除** – 確認後に削除します。

サーバー上で実行されているGramps Webの新しいバージョンで作成されたバックアップは警告アイコンでマークされ、復元できません。

### バックアップからの復元

保存されたバックアップまたはアップロードされたファイルからツリーを復元します。保存されたバックアップを復元するには、その横の復元ボタンをクリックします。ファイルから復元するには、Gramps Webバックアップ（`.tar`）またはGramps XMLファイル（`.gramps`）を選択し、**復元**をクリックします。

!!! danger
    データの復元は破壊的な置き換えであり、マージではありません。バックアップに存在しない既存のオブジェクトは削除されます。

Gramps Webバックアップの場合、バックアップが作成された日時、どのツリーのものであるか、どのバージョンであるかが表示され、復元する部分を選択できます：

- **データ** – 家系図のオブジェクト
- **ツリー設定** – このページの設定、テーマカラー、アプリタイトル、ホームページノートなど
- **ユーザー** – ツリーのユーザー

**プレビュー**をクリックすると、復元によって何が変更されるかを確認できます。Gramps XMLファイルはデータのみを含むため、そのようなファイルの場合、プレビューはすぐに開始されます。セッションが十分に新しくない場合、再認証を求められます。プレビューはバックグラウンドタスクとして実行され、完了すると、オブジェクトタイプごとの変更の要約（人物、家族、イベント、場所、引用、ソース、リポジトリ、メディアオブジェクト、ノート、タグ）、および選択された場合のツリー設定とユーザーの要約ダイアログが開きます：

- **追加** – バックアップに存在するが現在のツリーに欠けているオブジェクト
- **更新** – 両方に存在するが異なるオブジェクト
- **削除** – 現在のツリーに存在せず、バックアップに欠けているオブジェクト
- **変更なし** – 両方で同一のオブジェクト

削除されるオブジェクトがある場合、ダイアログはその数を警告します。要約を確認し、変更を適用するには**復元**をクリックし、取り消すには**キャンセル**をクリックします。

復元後、バックアップから追加されたユーザーがリストされます。彼らにはランダムなパスワードが与えられるため、サインインする前にパスワードをリセットする必要があります。サーバー上に既に存在するユーザーは変更されません。サーバー上でファイルが欠けているメディアオブジェクトもリストされます。これらは[メディアアーカイブのインポート](#import-media-archive)を介してアップロードします。

!!! note
    データの復元はオブジェクトデータとメディアリファレンスのみを復元します。バイナリメディアファイル自体やツリーのメタデータ（デフォルトの人物、ブックマーク、名前グループ）は影響を受けません。

!!! tip
    これを使用して、悪いインポートや不要な一括編集の後に、ツリーを既知の良好なバックアップに戻すことができます。

## 危険ゾーン

!!! danger
    危険ゾーンのアクションは**元に戻せません**。進む前に[バックアップ](#backups)を作成してください。

### すべてのオブジェクトを削除

家系図からオブジェクトを削除します。**削除**をクリックすると、次の削除オプションを選択できるダイアログが開きます：

- **すべてのオブジェクト** – ツリーを完全にクリアします
- **特定のオブジェクトタイプ** – 例えば、イベントのみまたはメディアオブジェクトのみ

アクションを確認するために再認証（再ログイン）を求められます。削除はバックグラウンドタスクとして実行され、進行状況インジケーターが表示されます。

!!! warning
    オブジェクトタイプのサブセットのみを削除する（すべてのオブジェクトを一度に削除するのではなく）と、大きなツリーの場合、オブジェクト間のすべての関係をチェックして更新する必要があるため、非常に長い時間がかかることがあります。

!!! tip
    これを使用して、新しいツリーをインポートする前に新たに始めるか、誤ってインポートされた特定のオブジェクトタイプを削除します。
