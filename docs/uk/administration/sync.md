# Синхронізація Gramps Web і Gramps Desktop

*Gramps Web Sync* — це доповнення для Gramps, яке дозволяє синхронізувати вашу базу даних Gramps на вашому настільному комп'ютері з Gramps Web, включаючи медіафайли.

!!! warning
    Як і з будь-яким інструментом синхронізації, не вважайте це інструментом резервного копіювання. Випадкове видалення з одного боку буде поширене на інший бік. Переконайтеся, що ви регулярно створюєте резервні копії (у форматі Gramps XML) вашого родинного дерева.

!!! info
    Документація стосується останньої версії доповнення Gramps Web Sync. Будь ласка, використовуйте менеджер доповнень Gramps, щоб оновити доповнення до останньої версії, якщо це необхідно.

!!! note "Що змінилося у версії 1.5"
    Інтерфейс доповнення був переписаний у версії 1.5. Крок за кроком майстер зник, його замінив одне вікно, а медіафайли тепер підтверджуються разом зі змінами об'єктів, а не на окремій сторінці пізніше. Якщо ви шукаєте селектор режиму синхронізації, він тепер знаходиться **над** списком змін, а не під ним. Режим синхронізації **злиття** був видалений; дивіться [Режим синхронізації](#sync-mode) нижче.

## Встановлення

Доповнення вимагає Gramps 6.0, що працює на Python 3.10 або новішій версії. 
Воно доступне в Gramps Desktop і може бути встановлене [звичним способом](https://www.gramps-project.org/wiki/index.php/5.2_Addons#Installing_Addons_in_Gramps).

!!! warning
    Будь ласка, переконайтеся, що ви використовуєте ту ж версію Gramps на вашому настільному комп'ютері, що й на вашому сервері. Дивіться розділ [Отримати допомогу](../help/help.md) для того, щоб дізнатися, яка версія Gramps працює на вашому сервері. Версія Gramps має форму `MAJOR.MINOR.PATCH`, і `MAJOR` та `MINOR` повинні бути однаковими на веб- та настільній версії.

### Вимоги до сервера

Доповнення перевіряє дві речі про ваш сервер, як тільки підключається, і відмовляється продовжувати, якщо одна з них не виконується. Обидві перевірки відбуваються перед завантаженням будь-якого вмісту.

- **Версія Gramps Web API 3.x.** Ця версія доповнення, для Gramps 6.0, працює з Gramps Web API 3. Старий сервер потребує оновлення; сервер, що працює на *новішій* основній версії API, потребує новішої версії Gramps, а не новішого доповнення, оскільки кожна лінія випуску Gramps парує з однією версією API. Ви можете знайти версію вашого сервера у *Налаштування ▸ Інформація про версію* в Gramps Web.
- **Черга фонових завдань.** Синхронізація подає свої зміни як фонове завдання. На сервері без налаштованої черги завдань застосування змін відбуватиметься синхронно і перевищить час на будь-якому реальному родинному дереві, тому доповнення відмовляється почати, а не зазнати невдачі на півдорозі.

Вам також потрібен обліковий запис з принаймні правами редактора, щоб застосовувати зміни до віддаленої бази даних.

Додатковий крок:

??? note inline end "Помилка в Gnome keyring"
    Наразі існує [помилка в python keyring](https://github.com/jaraco/keyring/issues/496), яка впливає на багато конфігурацій робочого столу Gnome. Вам може знадобитися створити файл конфігурації `~/.config/python_keyring/keyringrc.cfg` і відредагувати його, щоб виглядало так:

        [backend]
        default-keyring=keyring.backends.SecretService.Keyring

- Встановіть `keyring` (наприклад, `sudo apt install python3-keyring` або `sudo dnf install python3-keyring`), щоб дозволити зберігати пароль API безпечно у менеджері паролів вашої системи.

Якщо keyring не може бути використаний, доповнення про це повідомить і продовжить без нього — вам просто буде запропоновано ввести свій пароль щоразу. У пакеті Gramps **Snap** системний keyring заблокований через обмеження, поки ви не підключите інтерфейс один раз:

```bash
snap connect gramps:password-manager-service
```

Доповнення показує цю точну команду, коли виявляє ситуацію.

## Використання

Після встановлення доповнення доступне в Gramps під *Інструменти ▸ Обробка родинного дерева ▸ Gramps&nbsp;Web&nbsp;Sync*. Після підтвердження діалогового вікна з попередженням про те, що історія скасування буде скасована, відкривається вікно синхронізації.

**Жодні зміни не застосовуються до вашого локального дерева або до сервера, поки ви їх не підтвердите.**

У вікні є смуга вгорі, що називає родинне дерево, з яким ви синхронізуєтеся, обліковий запис і адресу, до яких воно належить, і коли воно востаннє синхронізувалося. Внизу показуються версії доповнення та веб-API сервера — корисно при повідомленні про проблему.

### Підключення

Якщо ви вже синхронізували це родинне дерево раніше, і ваш пароль збережено, доповнення підключається, як тільки відкривається, і переходить безпосередньо до порівняння. В іншому випадку воно запитує базову URL-адресу вашого екземпляра Gramps Web (приклад: `https://mygrampsweb.com/`), ваше ім'я користувача та пароль.

URL-адреса та ім'я користувача зберігаються у відкритому тексті у вашій директорії користувача Gramps. Пароль зберігається лише у вашому системному менеджері паролів, якщо ви залишаєте позначеним параметр **Запам'ятати пароль**; зняття позначки видаляє будь-який пароль, вже збережений для цього сервера.

!!! tip "Кілька родинних дерев, кілька серверів"
    Кожен сервер, з яким ви синхронізуєтеся, зберігається окремо, разом зі своїм записом про те, коли він востаннє синхронізувався. Чередування між двома серверами більше не порушує жоден з них.

    Кожен запис також фіксує **яке локальне родинне дерево** було востаннє синхронізовано. Доповнення підключається самостійно лише тоді, коли це відповідає дереву, яке ви відкрили; в іншому випадку воно показує деталі підключення і чекає, поки ви натиснете *Підключитися*, з попередженням, якщо збережені облікові дані належать до іншого дерева. Це важливо, оскільки синхронізація дерева з сервером, що містить *інше* дерево, призведе до пропозиції видалити вміст обох.

Доступні дві дії, поки нічого не записується:

- **Змінити сервер…**, на верхній смузі, повертає до деталей підключення, щоб ви могли вказати це дерево на іншому сервері. Це перериває порівняння, що триває, а не змушує вас чекати, поки воно закінчиться.
- **Забути цей сервер**, на панелі підключення, видаляє збережену адресу, ім'я користувача та пароль, разом із записом про те, коли це дерево востаннє синхронізувалося. Наступна синхронізація порівнює два дерева з нуля.

Якщо ви введете адресу, що починається з `http://`, а не з `https://`, під час введення з'явиться попередження. Ваш пароль буде надіслано у відкритому тексті, тому використовуйте його лише для локального тестування.

### Перегляд змін

Доповнення порівнює локальні та віддалені бази даних і показує, що воно пропонує зробити. На відміну від попередніх версій, які перераховували сирі відмінності між двома деревами, список тепер показує **дії**, які будуть виконані, згруповані за тим, яка база даних їх змінює:

```
▾ Зміниться на цьому комп'ютері (7 об'єктів)
    ▾ Додати 3 об'єкти
        Особа   Джон Сміт        I0123
    ▾ Оновити 4 об'єкти
        …
▾ Зміниться на сервері (5 об'єктів)
    …
```

Кожен рядок називає об'єкт, тому ви можете зрозуміти, хто або що підлягає змінам, а не лише бачити ID Gramps.

Якщо щось буде видалено, попередження над списком говорить, скільки об'єктів і з якого боку. Це з'являється щоразу, коли залучені видалення, включаючи під час звичайної двосторонньої синхронізації, що поширює видалення, яке ви зробили самі.

Натисніть **Застосувати**, щоб виконати те, що описує список.

!!! warning "Не редагуйте під час перегляду"
    Вікно синхронізації не блокує решту Gramps, тому ви можете продовжувати працювати, поки список відкритий. Якщо ви редагуєте об'єкт, на який це впливає, доповнення виявляє це, коли ви натискаєте Застосувати, зупиняється без внесення змін і просить вас порівняти ще раз. Нічого не втрачається, але порівняння потрібно повторити.

#### Режим синхронізації

Режим синхронізації вибирається **над** списком змін. Зміна його перезавантажує список, оскільки режим визначає, що кожна відмінність насправді стає.

- **Двостороння синхронізація** (за замовчуванням) — зміни з обох боків об'єднуються. Об'єкти, відредаговані в обох місцях, зливаються.
- **Скинути сервер, щоб відповідати цьому комп'ютеру** — сервер налаштовується відповідно до цього комп'ютера. Усе, що змінено лише на сервері, скидається.
- **Скинути цей комп'ютер, щоб відповідати серверу** — цей комп'ютер налаштовується відповідно до сервера. Усе, що змінено лише тут, скидається.

!!! note
    Режим **злиття**, доступний у попередніх версіях, був видалений. Він відрізнявся від двосторонньої синхронізації лише в тому, що відновлював об'єкти, видалені з одного боку, замість того, щоб поширювати видалення, що не було відмінністю, яку інтерфейс міг би пояснити корисно. Якщо ви покладалися на це, використовуйте двосторонню синхронізацію та відновлюйте все, що хочете зберегти з резервної копії.

### Медіафайли

Медіафайли обробляються як частина того ж підтвердження, а не як окремий крок. Якщо потрібно передати будь-які файли, під списком пропонується прапорець для їх переміщення:

```
[x] Також передати 12 медіафайлів (4 для завантаження, 8 для завантаження)
```

Зніміть позначку, щоб синхронізувати зміни об'єктів, не торкаючись файлів.

Файли, які відсутні на *обох* сторонах, перераховуються окремо, оскільки нічого не можна зробити з ними:

```
2 медіафайли відсутні на обох сторонах і не можуть бути передані.
```

Зверніть увагу на наступні обмеження синхронізації медіафайлів:

- Якщо локальний файл має інший контрольний підпис, ніж той, що зберігається в базі даних Gramps (це може статися, наприклад, для файлів Word, коли їх редагують після додавання до Gramps), завантаження зазнає невдачі з повідомленням про помилку.
- Інструмент не перевіряє цілісність усіх локальних файлів, тому якщо локальний файл існує за шляхом, збереженим для медіаоб'єкта, але файл відрізняється від файлу на сервері, інструмент цього не виявить. Використовуйте доповнення Media Verify, щоб виявити файли з неправильними контрольними підписами.

### Коли щось йде не так

Якщо синхронізація зазнає невдачі на півдорозі — наприклад, через обірване з'єднання — доповнення повідомляє, що вже було застосовано, і пропонує **Спробувати знову**, що відновлює з кроку, на якому сталася невдача, а не починає спочатку. Завантажена копія віддаленого дерева зберігається, тому повторна спроба не завантажує і не порівнює її вдруге.

Технічні деталі невдачі доступні за допомогою розгортання *Деталі*, з кнопкою для їх копіювання для звіту про помилку.

## Устранення неполадок

### Журнал налагодження

Якщо ви стикаєтеся з проблемами з доповненням Sync, будь ласка, запустіть Gramps з увімкненим журналом налагодження, [запустивши Gramps з командного рядка](https://gramps-project.org/wiki/index.php/Gramps_5.2_Wiki_Manual_-_Command_Line) з наступним параметром:

```bash
gramps --debug grampswebsync
```

Це надрукує багато корисних журналів на командному рядку, які допоможуть вам визначити причину проблеми.

### Облікові дані сервера

Якщо підключення не вдається, будь ласка, двічі перевірте URL-адресу сервера, ваше ім'я користувача та пароль.

### Доповнення відмовляється підключатися

Якщо доповнення повідомляє, що версія Gramps Web API сервера занадто стара або занадто нова, або що черга фонових завдань не налаштована, дивіться [Вимоги до сервера](#server-requirements) вище. Ці перевірки виконуються перед усім іншим, тому повідомлення безпосередньо вказує на проблему.

### Проблеми з правами

Якщо ви стикаєтеся з помилкою, що стосується прав, будь ласка, перевірте роль користувача вашого облікового запису Gramps Web. Ви можете застосовувати зміни до віддаленої бази даних лише якщо ви є користувачем з роллю редактора, власника або адміністратора.

### Несподівані зміни в базі даних

Якщо інструмент синхронізації виявляє зміни, які, на вашу думку, не відбулися, можливо, є невідповідності в одній з баз даних, які вводять Gramps в оману, або час не синхронізовано між вашим локальним комп'ютером і сервером.

Будь ласка, перевірте, що годинники на обох машинах правильно налаштовані (зауважте, що часова зона не має значення, оскільки інструмент використовує Unix-мітки часу, які не залежать від часової зони).

Ви також можете запустити інструмент перевірки та ремонту на вашій локальній базі даних і подивитися, чи це допоможе.

Простий, але ефективний метод, щоб переконатися, що невідповідності у вашій локальній базі даних не викликають хибних позитивів, — це експортувати вашу базу даних у формат Gramps XML і повторно імпортувати її в нову, порожню базу даних. Це безвтратна операція, але забезпечує, що всі дані імпортуються послідовно.

!!! tip
    Якщо доповнення пропонує тривожну кількість видалень, спочатку перевірте верхню смугу: вона називає родинне дерево на сервері, до якого ви збираєтеся записати. Синхронізація з сервером, що містить *інше* дерево, викликає саме цей симптом.

### Помилки тайм-ауту

Синхронізація з сервером обробляється фоновим робітником, тому тривалі синхронізації не повинні перевищувати час. Сервер без налаштованої черги завдань відмовляється на етапі підключення з цієї причини — дивіться [Вимоги до сервера](#server-requirements).

Запити від доповнення до сервера перевищують час після 60 секунд без відповіді, тому недоступний сервер повідомляє про помилку з'єднання замість того, щоб зависати безкінечно.

### Несподівані помилки медіафайлів

Якщо завантаження медіафайлу зазнає невдачі, це часто викликано невідповідністю контрольного підпису фактичного файлу на диску та контрольного підпису в локальній базі даних Gramps. Це часто трапляється з редагованими файлами, такими як офісні документи, відредаговані поза Gramps. Будь ласка, використовуйте доповнення Gramps Media Verify, щоб виправити контрольні підписи всіх медіафайлів.

### Запитайте допомогу

Якщо все вищезазначене не допомагає, ви можете звернутися до спільноти за допомогою, опублікувавши в [категорії Gramps Web форуму Gramps](https://gramps.discourse.group/c/gramps-web/28). Будь ласка, переконайтеся, що ви надали:

- версію доповнення Gramps Web Sync (і використовуйте, будь ласка, останню випущену версію) — вона показується внизу вікна синхронізації, поруч з версією веб-API сервера
- версію Gramps desktop, яку ви використовуєте
- вивід журналу налагодження Gramps, увімкненого, як описано вище
- інформацію про версію Gramps Web (ви можете знайти її в Налаштуваннях/Інформація про версію)
- будь-які деталі, які ви можете надати про вашу установку Gramps Web (самостійно хостинг, Grampshub тощо)
- вивід журналів вашого сервера Gramps Web, якщо у вас є до них доступ (при використанні docker: `docker compose logs --tail 100 grampsweb` та `docker compose logs --tail 100 grampsweb-celery`)

## Фон: як працює доповнення

Якщо вам цікаво, як насправді працює доповнення, ви можете знайти більше деталей у цьому розділі.

Доповнення призначене для підтримки локальної бази даних Gramps у синхронізації з віддаленою базою даних Gramps Web, щоб дозволити як локальні, так і віддалені зміни (колективне редагування).

Воно **не підходить**

- Для синхронізації з базою даних, яка не є прямим похідним (починаючи з копії бази даних або експорту/імпорту Gramps XML) локальної бази даних
- Для злиття двох баз даних з великою кількістю змін з обох боків, які потребують ручної уваги для злиття. Використовуйте відмінний [Інструмент імпорту злиття](https://www.gramps-project.org/wiki/index.php/Import_Merge_Tool) для цієї мети.

Принципи роботи інструменту дуже прості:

- Він порівнює локальні та віддалені бази даних
- Якщо є якісь відмінності, він перевіряє мітку часу останнього ідентичного об'єкта, назвемо його **t**
- Якщо об'єкт змінився пізніше, ніж **t**, існує в одній базі даних, але не в іншій, він синхронізується до обох (припустимо, новий об'єкт)
- Якщо об'єкт змінився востаннє до **t** і відсутній в одній базі даних, він видаляється в обох (припустимо, видалений об'єкт)
- Якщо об'єкт різний, але змінився після **t** лише в одній базі даних, синхронізуйте до іншої (припустимо, модифікований об'єкт)
- Якщо об'єкт різний, але змінився після **t** в обох базах даних, злийте їх (припустимо, конфліктуюче модифікування)

Час останньої успішної синхронізації також записується, окремо для кожного сервера, і використовується як **t**, коли він новіший за найновіший ідентичний об'єкт.

Цей алгоритм простий і надійний, оскільки не вимагає відстеження історії синхронізації. Однак він працює найкраще, коли ви *синхронізуєте часто*.
