# Конфігурація сервера

Використовуючи стандартний образ Docker, усю необхідну конфігурацію можна виконати у браузері. Однак залежно від способу розгортання може виникнути потреба налаштувати конфігурацію сервера.

На цій сторінці наведено всі способи зміни конфігурації та всі наявні параметри конфігурації.


## Файл конфігурації та змінні середовища

Для налаштувань можна використовувати файл конфігурації або змінні середовища.

Якщо ви використовуєте [налаштування на основі Docker Compose](deployment.md), ви можете підключити файл конфігурації, додавши наведений нижче елемент списку під ключем `volumes:` у блоці `grampsweb:`:

```yaml
      - /path/to/config.cfg:/app/config/config.cfg
```
де `/path/to/config.cfg` — шлях до файлу конфігурації у файловій системі вашого сервера (права частина посилається на шлях у контейнері, і її не можна змінювати).

Якщо ви використовуєте змінні середовища,

- додайте префікс `GRAMPSWEB_` до кожного імені параметра, щоб отримати ім’я змінної середовища
- Використовуйте подвійне підкреслення для вкладених параметрів словника, наприклад `GRAMPSWEB_THUMBNAIL_CACHE_CONFIG__CACHE_DEFAULT_TIMEOUT` встановить значення параметра конфігурації `THUMBNAIL_CACHE_CONFIG['CACHE_DEFAULT_TIMEOUT']`

Зауважте, що параметри конфігурації, задані через середовище, мають пріоритет над параметрами у файлі конфігурації. Якщо присутні обидва варіанти, «перемагає» змінна середовища.

!!! warning "Змінні середовища без префікса застаріли"
    З історичних причин кілька параметрів — `TREE`, `SECRET_KEY`, `USER_DB_URI`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `MEDIA_BASE_DIR`, `SEARCH_INDEX_DIR`, `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `DEFAULT_FROM_EMAIL`, `BASE_URL` і `STATIC_PATH` — усе ще можна задавати через змінну середовища *без* префікса `GRAMPSWEB_`. Це застарілий спосіб, під час запуску виводиться відповідне попередження, а в майбутньому випуску він перестане працювати. Завжди використовуйте форму з префіксом, наприклад `GRAMPSWEB_TREE` замість `TREE`.

    Зауважте, що це стосується лише змінних середовища. У файлі конфігурації імена параметрів завжди використовуються без префікса.

!!! tip "Перевірка застарілих параметрів"
    Застарілі параметри конфігурації, від яких досі залежить ваш сервер, — наприклад змінні середовища без префікса, `SEARCH_INDEX_DIR` або `EMAIL_USE_TLS` — під час запуску реєструються як попередження. Починаючи з Gramps Web API 3.22, вони також відображаються разом із заміною та версією, у якій підтримку буде вилучено, у верхній частині сторінки **Системна інформація** (доступної через піктограму користувача на верхній панелі застосунку), коли ви ввійшли як адміністратор.

    Налаштування електронної пошти та базова URL-адреса, які майстер першого запуску старіших версій зберігав у базі даних, також відображаються там. Задайте їх у конфігурації відповідно до збережених значень; попередження зникне, щойно вони збігатимуться.

## Наявні параметри конфігурації
Нижче наведено наявні параметри конфігурації.

### Обов’язкові параметри

Key | Description
----|-------------
`TREE` | Назва бази даних родинного дерева, яку слід використовувати. Перегляньте доступні дерева за допомогою `gramps -l`. Якщо дерева з такою назвою не існує, буде створено нове порожнє дерево.
`SECRET_KEY` | Секретний ключ для Flask. Секрет не можна публічно розголошувати. Його зміна зробить недійсними всі маркери доступу.
`USER_DB_URI` | URL-адреса бази даних користувачів. Дозволено будь-яку URL-адресу, сумісну із SQLAlchemy.

!!! info
    Ви можете згенерувати надійний секретний ключ, наприклад, за допомогою команди

    ```
    python3 -c "import secrets;print(secrets.token_urlsafe(32))"
    ```

### Необов’язкові параметри

Key | Description
----|-------------
`MEDIA_BASE_DIR` | Шлях, який слід використовувати як базовий каталог для мультимедійних файлів, замінюючи базовий каталог медіа, заданий у Gramps. У разі використання [S3](s3.md) має мати форму `s3://<bucket_name>`
`TREE_ID` | Назва каталогу бази даних родинного дерева, яку слід використовувати в режимі одного дерева (коли для `TREE` не задано значення `*`). Якщо задано, сервер ідентифікує дерево за назвою його каталогу, а не за відображуваною назвою, що надійніше під час перейменування. Потрібен, якщо ви хочете перейменувати дерево через API. Назву каталогу можна знайти за допомогою `GET /api/trees/-` (поле `id`).
`SEARCH_INDEX_DB_URI` | URL-адреса бази даних для пошукового індексу. Як серверні модулі дозволено лише `sqlite` або `postgresql`. Типове значення — `sqlite:///indexdir/search_index.db`, що створює файл SQLite у папці `indexdir` відносно шляху, з якого запущено скрипт
`SEARCH_INDEX_DIR` | **Застаріло** (замість цього використовуйте `SEARCH_INDEX_DB_URI`). Каталог, що містить пошуковий індекс. Якщо задано, а `SEARCH_INDEX_DB_URI` не задано, URL-адреса пошукового індексу виводиться як `sqlite:///<SEARCH_INDEX_DIR>/search_index.db`.
`STATIC_PATH` | Шлях, із якого слід обслуговувати статичні файли (наприклад, статичний вебінтерфейс)
`BASE_URL` | Базова URL-адреса, за якою можна отримати доступ до API (наприклад, `https://mygramps.mydomain.com/`). Вона потрібна, зокрема, для створення правильних посилань на скидання пароля. Для Web Push також потрібна загальнодоступна URL-адреса HTTPS; типова `http://localhost/` вимикає Web Push. Під час налаштування цього параметра через середовище використовуйте `GRAMPSWEB_BASE_URL`.
`CORS_ORIGINS` | Джерела, з яких дозволено CORS-запити. Типово всі джерела заборонені. Використовуйте `"*"`, щоб дозволити запити з будь-якого домену.
`EMAIL_HOST` | Хост SMTP-сервера (наприклад, для надсилання електронних листів зі скиданням пароля)
`EMAIL_PORT` | Порт SMTP-сервера. Типово — 465
`EMAIL_HOST_USER` | Ім’я користувача SMTP-сервера
`EMAIL_HOST_PASSWORD` | Пароль SMTP-сервера
`EMAIL_USE_TLS` | **Застаріло** (замість цього використовуйте `EMAIL_USE_SSL` або `EMAIL_USE_STARTTLS`). Логічне значення, що визначає, чи використовувати TLS для надсилання електронних листів. Типово — `True`. У разі використання STARTTLS встановіть значення `False` і використовуйте порт, відмінний від 25.
`EMAIL_USE_SSL` | Логічне значення, що визначає, чи використовувати неявний SSL/TLS для SMTP (v3.6.0+). Типово — `True`, якщо `EMAIL_USE_TLS` явно не задано. Зазвичай використовується з портом 465.
`EMAIL_USE_STARTTLS` | Логічне значення, що визначає, чи використовувати явний STARTTLS для SMTP (v3.6.0+). Типово — `False`. Зазвичай використовується з портом 587 або 25.
`DEFAULT_FROM_EMAIL` | Адреса «Від» для автоматичних електронних листів
`THUMBNAIL_CACHE_CONFIG` | Словник із параметрами кешу ескізів. Див. [Flask-Caching](https://flask-caching.readthedocs.io/en/latest/) щодо можливих параметрів.
`REQUEST_CACHE_CONFIG` | Словник із параметрами кешу запитів. Див. [Flask-Caching](https://flask-caching.readthedocs.io/en/latest/) щодо можливих параметрів.
`PERSISTENT_CACHE_CONFIG` | Словник із параметрами постійного кешу, який використовується, наприклад, для телеметрії. Див. [Flask-Caching](https://flask-caching.readthedocs.io/en/latest/) щодо можливих параметрів.
`CELERY_CONFIG` | Параметри черги фонових завдань Celery. Див. [Celery](https://docs.celeryq.dev/en/stable/userguide/configuration.html) щодо можливих параметрів.
`REPORT_DIR` | Тимчасовий каталог, у якому зберігатимуться результати виконання звітів Gramps
`EXPORT_DIR` | Тимчасовий каталог, у якому зберігатимуться результати експорту бази даних Gramps
`BACKUP_DIR` | Каталог, у якому зберігаються [резервні копії](../administration/backups.md), у підкаталозі для кожного дерева (v3.24.0+). Якщо не задано (типове значення), резервні копії не можна зберігати на сервері, але їх можна відновлювати із завантаженого файлу. Використовуйте постійне розташування, наприклад том Docker, і бажано таке, яке також резервується або синхронізується в іншому місці.
`BACKUP_KEEP` | Кількість збережених резервних копій для кожного дерева; старіші копії видаляються під час створення нової резервної копії (v3.24.0+). Типове значення — `5`
`RATE_LIMIT_BACKUP` | Обмеження частоти створення резервних копій для кожного дерева (v3.24.0+). Типове значення — `"10 per day"`
`RATE_LIMIT_MEDIA_ARCHIVE` | Обмеження частоти створення медіаархівів на сторінці експорту. Типове значення — `"1 per hour"`
`REGISTRATION_DISABLED` | Якщо `True`, заборонити реєстрацію нових користувачів (типове значення — `False`). Починаючи з Gramps Web API 3.26, сторінка входу також приховує посилання на реєстрацію.
`PROXY_FIX_X_FOR` | Кількість довірених зворотних проксі перед Gramps Web (v3.26.0+). Встановіть значення `1`, якщо використовується один зворотний проксі, щоб обмеження частоти застосовувалися для кожного клієнта, а не для всіх користувачів разом. Типове значення — `0`. Встановлюйте цей параметр лише тоді, коли доступ до сервера здійснюється виключно через ці проксі.
`DISABLE_TELEMETRY` | Якщо `True`, вимкнути телеметрію статистики (типове значення — `False`). Докладніше див. у розділі [телеметрія](telemetry.md).
`PILLOW_MAX_IMAGE_PIXELS` | Встановлює параметр `PIL.Image.MAX_IMAGE_PIXELS`, який визначає кількість пікселів, що може містити оброблюване зображення. Докладніше див. у [документації](https://pillow.readthedocs.io/en/stable/reference/Image.html#PIL.Image.MAX_IMAGE_PIXELS).
`MAX_THUMBNAIL_FILE_BYTES` | Встановлює максимальний розмір файлу для ескізів. Типове значення — `50 * 1024 * 1024` (50 МБ). Його збільшення може значно підвищити використання пам’яті та призвести до аварійного завершення через нестачу пам’яті або втрати даних, якщо великі файли розпаковуються в пам’яті.


!!! info
    Під час використання змінних середовища для конфігурації логічні параметри, такі як `EMAIL_USE_SSL`, мають бути рядком `true` або `false` (з урахуванням регістру!).


### Параметри для баз даних PostgreSQL

Ці параметри потрібні, якщо ваші родинні дерева розміщено в [базі даних PostgreSQL](postgres.md) із використанням додатка SharedPostgreSQL.

Key | Description
----|-------------
`POSTGRES_USER` | Ім’я користувача для підключення до бази даних
`POSTGRES_PASSWORD` | Пароль користувача бази даних


### Параметри, важливі для розміщення кількох дерев

Наведені нижче параметри важливі під час [розміщення кількох дерев](multi-tree.md).


Key | Description
----|-------------
`MEDIA_PREFIX_TREE` | Логічне значення, що визначає, чи використовувати окрему підпапку для мультимедійних файлів кожного дерева. Типово — `False`, але для конфігурації з кількома деревами наполегливо рекомендується використовувати `True`
`NEW_DB_BACKEND` | Серверна частина бази даних, яку слід використовувати для новостворених родинних дерев. Має бути одним зі значень `sqlite` або `sharedpostgresql`. Типове значення — `sqlite`. Значення `postgresql` усе ще приймається, але є застарілим, оскільки серверну частину PostgreSQL буде вилучено з Gramps Web API 4.0.
`POSTGRES_HOST` | Ім’я хоста сервера PostgreSQL, який використовується для створення нових дерев під час використання конфігурації з кількома деревами та серверної частини SharedPostgreSQL
`POSTGRES_PORT` | Порт сервера PostgreSQL, який використовується для створення нових дерев під час використання конфігурації з кількома деревами та серверної частини SharedPostgreSQL


### Параметри автентифікації OIDC

Ці параметри потрібні, якщо ви хочете використовувати автентифікацію OpenID Connect (OIDC) із зовнішніми постачальниками. Докладні інструкції з налаштування та приклади див. у розділі [Автентифікація OIDC](oidc.md).

Key | Description
----|-------------
`OIDC_ENABLED` | Логічне значення, що визначає, чи ввімкнути автентифікацію OIDC. Типове значення — `False`.
`OIDC_ISSUER` | URL-адреса видавця постачальника OIDC (для користувацьких постачальників OIDC)
`OIDC_CLIENT_ID` | Ідентифікатор клієнта OAuth (для користувацьких постачальників OIDC)
`OIDC_CLIENT_SECRET` | Секрет клієнта OAuth (для користувацьких постачальників OIDC)
`OIDC_NAME` | Користувацька відображувана назва постачальника. Типове значення — "OIDC"
`OIDC_SCOPES` | Області OAuth. Типове значення — "openid email profile"
`OIDC_USERNAME_CLAIM` | Твердження, яке слід використовувати для імені користувача. Типове значення — "preferred_username"
`OIDC_OPENID_CONFIG_URL` | Необов’язково: URL-адреса кінцевої точки конфігурації OpenID Connect (якщо не використовується стандартна `/.well-known/openid-configuration`)
`OIDC_PKCE` | Логічне значення, що визначає, чи використовувати PKCE. Якщо не задано, PKCE використовується, коли документ виявлення постачальника містить `S256`. Див. [PKCE](oidc.md#pkce)
`OIDC_DISABLE_LOCAL_AUTH` | Логічне значення, що визначає, чи вимкнути локальну автентифікацію за іменем користувача та паролем. Типове значення — `False`
`OIDC_AUTO_REDIRECT` | Логічне значення, що визначає, чи автоматично перенаправляти до OIDC, коли налаштовано лише одного постачальника. Типове значення — `False`
`OIDC_ALLOWED_REDIRECT_URIS` | Список URI `https`, на які нативні застосунки можуть отримувати результат входу (v3.26.0+), заданий як список JSON у змінній середовища. Типово порожній. Потрібен лише тоді, коли це вимагає документація нативного застосунку. Див. [Нативні застосунки](oidc.md#native-apps)

#### Вбудовані постачальники OIDC

Для вбудованих постачальників (Google, Microsoft) використовуйте такі параметри:

Key | Description
----|-------------
`OIDC_GOOGLE_CLIENT_ID` | Ідентифікатор клієнта для Google OAuth
`OIDC_GOOGLE_CLIENT_SECRET` | Секрет клієнта для Google OAuth
`OIDC_MICROSOFT_CLIENT_ID` | Ідентифікатор клієнта для Microsoft OAuth
`OIDC_MICROSOFT_CLIENT_SECRET` | Секрет клієнта для Microsoft OAuth
`OIDC_GOOGLE_PKCE` | Параметр PKCE для Google, див. [PKCE](oidc.md#pkce)
`OIDC_MICROSOFT_PKCE` | Параметр PKCE для Microsoft, див. [PKCE](oidc.md#pkce)

#### Відображення ролей OIDC

Ці параметри дають змогу зіставляти групи/ролі OIDC від вашого постачальника ідентифікаційних даних із ролями користувачів Gramps Web:

Key | Description
----|-------------
`OIDC_ROLE_CLAIM` | Назва твердження в токені OIDC, що містить групи/ролі користувача. Типове значення — "groups"
`OIDC_GROUP_ADMIN` | Назва групи/ролі від вашого постачальника OIDC, яка відповідає ролі Gramps «Адміністратор»
`OIDC_GROUP_OWNER` | Назва групи/ролі від вашого постачальника OIDC, яка відповідає ролі Gramps «Власник»
`OIDC_GROUP_EDITOR` | Назва групи/ролі від вашого постачальника OIDC, яка відповідає ролі Gramps «Редактор»
`OIDC_GROUP_CONTRIBUTOR` | Назва групи/ролі від вашого постачальника OIDC, яка відповідає ролі Gramps «Учасник»
`OIDC_GROUP_MEMBER` | Назва групи/ролі від вашого постачальника OIDC, яка відповідає ролі Gramps «Член»
`OIDC_GROUP_GUEST` | Назва групи/ролі від вашого постачальника OIDC, яка відповідає ролі Gramps «Гість»

### Параметри лише для функцій ШІ

Ці параметри потрібні, якщо ви хочете використовувати чат зі ШІ. Докладніше див. у розділі [Налаштування чату зі ШІ](chat.md).

!!! note
    Параметри `VECTOR_EMBEDDING_MODEL`, `VECTOR_EMBEDDING_BASE_URL` і `VECTOR_EMBEDDING_API_KEY` для семантичного пошуку ігноруються починаючи з Gramps Web API 3.25, у якому семантичний пошук було вилучено. Для чату зі ШІ потрібен лише `LLM_MODEL`.

Key | Description
----|-------------
`LLM_BASE_URL` | Базова URL-адреса API чату, сумісного з OpenAI. Типове значення — `None`, що означає використання API OpenAI.
`LLM_MODEL` | Модель, яку слід використовувати для API чату, сумісного з OpenAI. Якщо не задано (типове значення), чат вимкнено. Починаючи з v3.6.0, помічник ШІ використовує Pydantic AI із можливостями виклику інструментів.
`LLM_MAX_OUTPUT_TOKENS` | Максимальна кількість токенів, яку модель може згенерувати в одній відповіді. Типово не задано, тому обмеження визначається сервером моделі. Корисно для серверів моделей, які не мають власного обмеження, оскільки інакше відповідь може тривати нескінченно.
`LLM_MAX_CONTEXT_LENGTH` | Обмеження кількості символів для контексту родинного дерева, що передається до LLM. Типове значення — 50000.
`LLM_SYSTEM_PROMPT` | Власний системний запит для помічника чату з LLM (v3.6.0+). Якщо не задано, використовується типовий запит, оптимізований для генеалогії.
`LLM_VISION` | Логічне значення, що визначає, чи можуть користувачі додавати зображення до своїх запитань (v3.26.0+). Вмикайте його лише в тому разі, якщо модель приймає зображення. Типове значення — `False`. Див. [Зображення в запитаннях](chat.md#images-in-questions)
`LLM_ALLOW_WRITE_PROPOSALS` | Логічне значення, що визначає, чи може помічник пропонувати зміни до дерева для перевірки та застосування користувачами (v3.26.0+). Типове значення — `False`. Див. [Дозвіл помічнику пропонувати зміни](chat.md#letting-the-assistant-propose-changes)


## Приклад файлу конфігурації

Мінімальний файл конфігурації для робочого середовища може мати такий вигляд:
```python
TREE="My Family Tree"
BASE_URL="https://mytree.example.com"
SECRET_KEY="..."  # ваш секретний ключ
USER_DB_URI="sqlite:////path/to/users.sqlite"
EMAIL_HOST="mail.example.com"
EMAIL_PORT=465
EMAIL_USE_SSL=True  # Використовувати неявний SSL для порту 465
EMAIL_HOST_USER="gramps@example.com"
EMAIL_HOST_PASSWORD="..." # ваш пароль SMTP
DEFAULT_FROM_EMAIL="gramps@example.com"
```
