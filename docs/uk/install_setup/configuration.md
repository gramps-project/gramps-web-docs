# Налаштування сервера

Використовуючи стандартний образ Docker, всі необхідні налаштування можна зробити з браузера. Однак, в залежності від розгортання, може знадобитися налаштувати конфігурацію сервера.

Ця сторінка містить всі методи зміни конфігурації та всі існуючі параметри конфігурації.


## Файл конфігурації проти змінних середовища

Для налаштувань ви можете використовувати або файл конфігурації, або змінні середовища.

Коли ви використовуєте [налаштування на основі Docker Compose](deployment.md), ви можете включити файл конфігурації, додавши наступний пункт списку під ключем `volumes:` в блоці `grampsweb:`:

```yaml
      - /path/to/config.cfg:/app/config/config.cfg
```
де `/path/to/config.cfg` - це шлях до файлу конфігурації у файловій системі вашого сервера (права сторона посилається на шлях у контейнері і не повинна змінюватися).

При використанні змінних середовища,

- префіксуйте кожну назву налаштування `GRAMPSWEB_`, щоб отримати назву змінної середовища
- Використовуйте подвійні підкреслення для вкладених налаштувань словника, наприклад, `GRAMPSWEB_THUMBNAIL_CACHE_CONFIG__CACHE_DEFAULT_TIMEOUT` встановить значення параметра конфігурації `THUMBNAIL_CACHE_CONFIG['CACHE_DEFAULT_TIMEOUT']`

Зверніть увагу, що параметри конфігурації, встановлені через середовище, мають перевагу над тими, що в файлі конфігурації. Якщо обидва присутні, змінна середовища "перемагає".

!!! warning "Змінні середовища без префікса застаріли"
    З історичних причин, кілька налаштувань – `TREE`, `SECRET_KEY`, `USER_DB_URI`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `MEDIA_BASE_DIR`, `SEARCH_INDEX_DIR`, `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `DEFAULT_FROM_EMAIL`, `BASE_URL`, і `STATIC_PATH` – все ще можуть бути встановлені через змінну середовища *без* префікса `GRAMPSWEB_`. Це застаріло, генерує попередження при запуску, і перестане працювати в майбутньому релізі. Завжди використовуйте префіксовану форму, наприклад, `GRAMPSWEB_TREE` замість `TREE`.

    Зверніть увагу, що це стосується лише змінних середовища. У файлі конфігурації назви налаштувань завжди використовуються без префікса.

!!! tip "Перевірка застарілих опцій"
    Застарілі параметри конфігурації, від яких ваш сервер все ще залежить – такі як змінні середовища без префікса, `SEARCH_INDEX_DIR`, або `EMAIL_USE_TLS` – реєструються як попередження при запуску. Починаючи з Gramps Web API 3.22, вони також перераховуються разом з їх заміною та версією, в якій підтримка буде видалена, на верху сторінки **Системна інформація** (доступна через іконку користувача в верхній панелі програми), коли ви увійшли як адміністратор.

    Налаштування електронної пошти та базова URL-адреса, які майстер першого запуску старіших версій зберігав у базі даних, також перераховуються там. Встановіть їх у своїй конфігурації на збережені значення; попередження зникає, як тільки вони збігаються.

## Існуючі налаштування конфігурації
Існують наступні параметри конфігурації.

### Обов'язкові налаштування

Ключ | Опис
----|-------------
`TREE` | Назва бази даних родинного дерева, яку слід використовувати. Показати доступні дерева за допомогою `gramps -l`. Якщо дерева з цією назвою не існує, буде створено нове порожнє.
`SECRET_KEY` | Секретний ключ для Flask. Секрет не повинен бути опублікований публічно. Зміна його анулює всі токени доступу.
`USER_DB_URI` | URL бази даних користувачів. Дозволяється будь-який URL, сумісний з SQLAlchemy.

!!! info
    Ви можете згенерувати безпечний секретний ключ, наприклад, за допомогою команди

    ```
    python3 -c "import secrets;print(secrets.token_urlsafe(32))"
    ```

### Додаткові налаштування

Ключ | Опис
----|-------------
`MEDIA_BASE_DIR` | Шлях, який слід використовувати як базовий каталог для медіафайлів, що замінює базовий каталог медіа, встановлений у Gramps. При використанні [S3](s3.md) повинен мати форму `s3://<bucket_name>`
`TREE_ID` | Назва каталогу бази даних родинного дерева, яку слід використовувати в режимі одного дерева (коли `TREE` не встановлено на `*`). Коли встановлено, сервер ідентифікує дерево за його назвою каталогу, а не за його відображуваною назвою, що є більш надійним при перейменуваннях. Обов'язково, якщо ви хочете перейменувати дерево через API. Назву каталогу можна знайти через `GET /api/trees/-` (поле `id`).
`SEARCH_INDEX_DB_URI` | URL бази даних для індексу пошуку. Дозволяються лише `sqlite` або `postgresql` як бекенди. За замовчуванням `sqlite:///indexdir/search_index.db`, створюючи файл SQLite в папці `indexdir`, відносно шляху, де запускається скрипт.
`SEARCH_INDEX_DIR` | **Застаріло** (використовуйте `SEARCH_INDEX_DB_URI` замість). Каталог, що містить індекс пошуку. Якщо встановлено, коли `SEARCH_INDEX_DB_URI` не встановлено, URL індексу пошуку отримується як `sqlite:///<SEARCH_INDEX_DIR>/search_index.db`.
`STATIC_PATH` | Шлях для обслуговування статичних файлів (наприклад, статичний веб-фронтенд)
`BASE_URL` | Базова URL-адреса, за якою можна отримати доступ до API (наприклад, `https://mygramps.mydomain.com/`). Це необхідно, наприклад, для створення правильних посилань для скидання пароля. Web Push також вимагає публічно доступну HTTPS URL-адресу; за замовчуванням `http://localhost/` відключає Web Push. При налаштуванні цього параметра через середовище використовуйте `GRAMPSWEB_BASE_URL`.
`CORS_ORIGINS` | Походження, з яких дозволені запити CORS. За замовчуванням всі заборонені. Використовуйте `"*"` для дозволу запитів з будь-якого домену.
`EMAIL_HOST` | Хост SMTP-сервера (наприклад, для надсилання електронних листів для скидання пароля)
`EMAIL_PORT` | Порт SMTP-сервера. за замовчуванням 465
`EMAIL_HOST_USER` | Ім'я користувача SMTP-сервера
`EMAIL_HOST_PASSWORD` | Пароль SMTP-сервера
`EMAIL_USE_TLS` | **Застаріло** (використовуйте `EMAIL_USE_SSL` або `EMAIL_USE_STARTTLS` замість). Логічне значення, чи використовувати TLS для надсилання електронних листів. За замовчуванням `True`. При використанні STARTTLS встановіть це значення на `False` і використовуйте порт, відмінний від 25.
`EMAIL_USE_SSL` | Логічне значення, чи використовувати неявний SSL/TLS для SMTP (v3.6.0+). За замовчуванням `True`, якщо `EMAIL_USE_TLS` не встановлено явно. Зазвичай використовується з портом 465.
`EMAIL_USE_STARTTLS` | Логічне значення, чи використовувати явний STARTTLS для SMTP (v3.6.0+). За замовчуванням `False`. Зазвичай використовується з портом 587 або 25.
`DEFAULT_FROM_EMAIL` | Адреса "Від" для автоматизованих електронних листів
`THUMBNAIL_CACHE_CONFIG` | Словник з налаштуваннями для кешу ескізів. Див. [Flask-Caching](https://flask-caching.readthedocs.io/en/latest/) для можливих налаштувань.
`REQUEST_CACHE_CONFIG` | Словник з налаштуваннями для кешу запитів. Див. [Flask-Caching](https://flask-caching.readthedocs.io/en/latest/) для можливих налаштувань.
`PERSISTENT_CACHE_CONFIG` | Словник з налаштуваннями для постійного кешу, що використовується, наприклад, для телеметрії. Див. [Flask-Caching](https://flask-caching.readthedocs.io/en/latest/) для можливих налаштувань.
`CELERY_CONFIG` | Налаштування для фонової черги завдань Celery. Див. [Celery](https://docs.celeryq.dev/en/stable/userguide/configuration.html) для можливих налаштувань.
`REPORT_DIR` | Тимчасовий каталог, де буде зберігатися вихід виконання звітів Gramps
`EXPORT_DIR` | Тимчасовий каталог, де буде зберігатися вихід експорту бази даних Gramps
`BACKUP_DIR` | Каталог, де зберігаються [резервні копії](../administration/settings.md#backups), у підкаталозі для кожного дерева (v3.24.0+). Якщо не встановлено (за замовчуванням), резервні копії не можуть зберігатися на сервері, але їх все ще можна відновити з завантаженого файлу. Використовуйте постійне місце, наприклад, об'єм Docker, і бажано таке, яке також резервується або синхронізується в іншому місці.
`BACKUP_KEEP` | Кількість збережених резервних копій на дерево; старі резервні копії видаляються, коли створюється нова резервна копія (v3.24.0+). За замовчуванням `5`
`RATE_LIMIT_BACKUP` | Ліміт швидкості для створення резервних копій, на дерево (v3.24.0+). За замовчуванням `"10 на день"`
`RATE_LIMIT_MEDIA_ARCHIVE` | Ліміт швидкості для створення медіаархівів на сторінці експорту. За замовчуванням `"1 на годину"`
`REGISTRATION_DISABLED` | Якщо `True`, заборонити реєстрацію нових користувачів (за замовчуванням `False`)
`DISABLE_TELEMETRY` | Якщо `True`, відключити статистичну телеметрію (за замовчуванням `False`). Див. [телеметрія](telemetry.md) для деталей.
`PILLOW_MAX_IMAGE_PIXELS` | Встановлює параметр PIL.Image.MAX_IMAGE_PIXELS, який вказує на кількість пікселів, які може містити оброблене зображення. Див. [документацію](https://pillow.readthedocs.io/en/stable/reference/Image.html#PIL.Image.MAX_IMAGE_PIXELS) для деталей.
`MAX_THUMBNAIL_FILE_BYTES` | Встановлює жорсткий максимальний розмір файлу для ескізів. За замовчуванням `50 * 1024 * 1024` (50 МБ). Підвищення цього значення може значно збільшити використання пам'яті і може призвести до аварій через нестачу пам'яті або втрати даних, якщо великі файли розпаковуються в пам'яті.


!!! info
    При використанні змінних середовища для конфігурації логічні параметри, такі як `EMAIL_USE_SSL`, повинні бути або рядком `true`, або `false` (регістр має значення!).


### Налаштування для баз даних PostgreSQL

Ці налаштування є обов'язковими, якщо ваші родинні дерева розміщені в [базі даних PostgreSQL](postgres.md) з використанням аддона SharedPostgreSQL.

Ключ | Опис
----|-------------
`POSTGRES_USER` | Ім'я користувача для підключення до бази даних
`POSTGRES_PASSWORD` | Пароль для користувача бази даних


### Налаштування, що стосуються розміщення кількох дерев

Наступні налаштування є актуальними при [розміщенні кількох дерев](multi-tree.md).


Ключ | Опис
----|-------------
`MEDIA_PREFIX_TREE` | Логічне значення, чи використовувати окрему підпапку для медіафайлів кожного дерева. За замовчуванням `False`, але настійно рекомендується використовувати `True` у налаштуванні з кількома деревами
`NEW_DB_BACKEND` | Бекенд бази даних, який слід використовувати для новостворених родинних дерев. Повинен бути одним з `sqlite` або `sharedpostgresql`. За замовчуванням `sqlite`. Значення `postgresql` все ще приймається, але застаріло, оскільки бекенд PostgreSQL буде видалено в Gramps Web API 4.0.
`POSTGRES_HOST` | Ім'я хоста сервера PostgreSQL, що використовується для створення нових дерев при використанні налаштування з кількома деревами з бекендом SharedPostgreSQL
`POSTGRES_PORT` | Порт сервера PostgreSQL, що використовується для створення нових дерев при використанні налаштування з кількома деревами з бекендом SharedPostgreSQL


### Налаштування для аутентифікації OIDC

Ці налаштування потрібні, якщо ви хочете використовувати аутентифікацію OpenID Connect (OIDC) з зовнішніми постачальниками. Для детальних інструкцій з налаштування та прикладів див. [Аутентифікація OIDC](oidc.md).

Ключ | Опис
----|-------------
`OIDC_ENABLED` | Логічне значення, чи дозволити аутентифікацію OIDC. За замовчуванням `False`.
`OIDC_ISSUER` | URL постачальника OIDC (для користувацьких постачальників OIDC)
`OIDC_CLIENT_ID` | OAuth ідентифікатор клієнта (для користувацьких постачальників OIDC)
`OIDC_CLIENT_SECRET` | OAuth секрет клієнта (для користувацьких постачальників OIDC)
`OIDC_NAME` | Користувацька відображувана назва для постачальника. За замовчуванням "OIDC"
`OIDC_SCOPES` | OAuth області. За замовчуванням "openid email profile"
`OIDC_USERNAME_CLAIM` | Заява, яку слід використовувати для імені користувача. За замовчуванням "preferred_username"
`OIDC_OPENID_CONFIG_URL` | Необов'язково: URL до кінцевої точки конфігурації OpenID Connect (якщо не використовується стандартний `/.well-known/openid-configuration`)
`OIDC_PKCE` | Логічне значення, чи використовувати PKCE. Якщо не встановлено, PKCE використовується, коли документ виявлення постачальника перераховує `S256`. Див. [PKCE](oidc.md#pkce)
`OIDC_DISABLE_LOCAL_AUTH` | Логічне значення, чи відключити локальну аутентифікацію за ім'ям користувача/паролем. За замовчуванням `False`
`OIDC_AUTO_REDIRECT` | Логічне значення, чи автоматично перенаправляти на OIDC, коли налаштовано лише одного постачальника. За замовчуванням `False`

#### Вбудовані постачальники OIDC

Для вбудованих постачальників (Google, Microsoft) використовуйте ці налаштування:

Ключ | Опис
----|-------------
`OIDC_GOOGLE_CLIENT_ID` | Ідентифікатор клієнта для Google OAuth
`OIDC_GOOGLE_CLIENT_SECRET` | Секрет клієнта для Google OAuth
`OIDC_MICROSOFT_CLIENT_ID` | Ідентифікатор клієнта для Microsoft OAuth
`OIDC_MICROSOFT_CLIENT_SECRET` | Секрет клієнта для Microsoft OAuth
`OIDC_GOOGLE_PKCE` | Логічне значення, налаштування PKCE для Google, див. [PKCE](oidc.md#pkce)
`OIDC_MICROSOFT_PKCE` | Логічне значення, налаштування PKCE для Microsoft, див. [PKCE](oidc.md#pkce)

#### Відображення ролей OIDC

Ці налаштування дозволяють вам відображати групи/ролі OIDC з вашого постачальника ідентичності на ролі користувачів Gramps Web:

Ключ | Опис
----|-------------
`OIDC_ROLE_CLAIM` | Назва заяви в токені OIDC, яка містить групи/ролі користувача. За замовчуванням "groups"
`OIDC_GROUP_ADMIN` | Назва групи/ролі з вашого постачальника OIDC, яка відображається на роль "Admin" Gramps
`OIDC_GROUP_OWNER` | Назва групи/ролі з вашого постачальника OIDC, яка відображається на роль "Owner" Gramps
`OIDC_GROUP_EDITOR` | Назва групи/ролі з вашого постачальника OIDC, яка відображається на роль "Editor" Gramps
`OIDC_GROUP_CONTRIBUTOR` | Назва групи/ролі з вашого постачальника OIDC, яка відображається на роль "Contributor" Gramps
`OIDC_GROUP_MEMBER` | Назва групи/ролі з вашого постачальника OIDC, яка відображається на роль "Member" Gramps
`OIDC_GROUP_GUEST` | Назва групи/ролі з вашого постачальника OIDC, яка відображається на роль "Guest" Gramps

### Налаштування лише для функцій ШІ

Ці налаштування потрібні, якщо ви хочете використовувати функції на основі ШІ, такі як чат або семантичний пошук. Див. [Налаштування AI чату](chat.md) для деталей.

!!! warning "Семантичний пошук застарілий"
    Семантичний пошук, і з ним налаштування `VECTOR_EMBEDDING_*`, застаріли і будуть видалені в Gramps Web API 3.25. Після цього `VECTOR_EMBEDDING_MODEL` все ще приймається, але ігнорується. Починаючи з Gramps Web API 3.24, AI чат потребує лише `LLM_MODEL`.

Ключ | Опис
----|-------------
`LLM_BASE_URL` | Базова URL-адреса для API чату, сумісного з OpenAI. За замовчуванням `None`, що використовує API OpenAI.
`LLM_MODEL` | Модель, яку слід використовувати для API чату, сумісного з OpenAI. Якщо не встановлено (за замовчуванням), чат відключено. Починаючи з v3.6.0, AI асистент використовує Pydantic AI з можливостями виклику інструментів.
`VECTOR_EMBEDDING_MODEL` | **Застаріло**, буде видалено в 3.25. Модель, яку слід використовувати для векторних вбудувань семантичного пошуку. При використанні локальної моделі це повинно бути ім'я моделі [Sentence Transformers](https://sbert.net/). При використанні віддаленого API (див. `VECTOR_EMBEDDING_BASE_URL`) це ім'я моделі, яке передається віддаленому постачальнику. Якщо не встановлено (за замовчуванням), семантичний пошук відключено. До Gramps Web API 3.24 чат також був відключено.
`VECTOR_EMBEDDING_BASE_URL` | **Застаріло**, буде видалено в 3.25. Базова URL-адреса для віддаленого API вбудовування, сумісного з OpenAI (наприклад, Ollama, OpenAI, LiteLLM). Якщо не встановлено (за замовчуванням), використовується локальна модель Sentence Transformers. Див. [Використання віддаленого API вбудовування](chat.md#using-a-remote-embedding-api) для деталей.
`VECTOR_EMBEDDING_API_KEY` | **Застаріло**, буде видалено в 3.25. API ключ для аутентифікованих віддалених постачальників вбудовування. Потрібен лише коли `VECTOR_EMBEDDING_BASE_URL` встановлено і постачальник вимагає аутентифікації.
`LLM_MAX_CONTEXT_LENGTH` | Обмеження символів для контексту родинного дерева, наданого LLM. За замовчуванням 50000.
`LLM_SYSTEM_PROMPT` | Користувацький системний запит для асистента чату LLM (v3.6.0+). Якщо не встановлено, використовується стандартний запит, оптимізований для генеалогії.
