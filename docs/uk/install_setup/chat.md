# Налаштування AI чату

!!! info
    AI чат вимагає Gramps Web API версії 2.5.0 або вище. Версія 3.6.0 ввела можливості виклику інструментів для більш інтелектуальних взаємодій.

Gramps Web API підтримує запитання про генеалогічну базу даних за допомогою великих мовних моделей (LLM) з викликом інструментів.

## Як це працює

AI асистент використовує спеціалізовані інструменти для запиту ваших генеалогічних даних безпосередньо. Ці інструменти дозволяють асистенту шукати в базі даних за допомогою повнотекстового пошуку, фільтрувати людей/події/сім'ї/місця за конкретними критеріями, обчислювати стосунки між особами та отримувати повні записи, включаючи нотатки. Асистент потім відповідає на основі записів, які він переглянув, і надає посилання на них у своїй відповіді. Він відповідає лише на основі дерева, а не з загальних знань: якщо в дереві нічого не зафіксовано, асистент про це повідомляє. Посилання на об'єкти, які не існують або є приватними для користувача, замінюються їх текстом.

AI чат не потребує моделі векторного вбудовування. Версії Gramps Web API до 3.24 також використовували *семантичний пошук* (пошук з підсиленням, RAG), який порівнював значення запитання з індексом числових векторів, обчислених для всіх об'єктів у базі даних. Семантичний пошук був видалений у Gramps Web API 3.25; параметри `VECTOR_EMBEDDING_MODEL`, `VECTOR_EMBEDDING_BASE_URL` та `VECTOR_EMBEDDING_API_KEY` ігноруються і можуть бути видалені з вашої конфігурації.

Щоб активувати кінцеву точку чату в Gramps Web API, необхідно виконати два кроки:

1. Встановлення необхідних залежностей,
2. Налаштування постачальника LLM.

Ці два кроки описані нижче по черзі. Нарешті, власник або адміністратор повинен [налаштувати, які користувачі можуть отримати доступ до функції чату](users.md#configuring-who-can-use-ai-chat) у налаштуваннях Керування користувачами.

## Встановлення необхідних залежностей

Стандартні образи Docker для Gramps Web вже мають всі необхідні залежності для AI чату попередньо встановленими.

При встановленні Gramps Web API через `pip` (це не потрібно при використанні образів Docker) необхідні залежності встановлюються за допомогою

```bash
pip install gramps_webapi[ai]
```

## Налаштування постачальника LLM

Зв'язок з LLM використовує фреймворк Pydantic AI, який підтримує API, сумісні з OpenAI. Це дозволяє використовувати локально розгорнуту LLM через Ollama (див. [Сумісність Ollama з OpenAI](https://ollama.com/blog/openai-compatibility)) або хостингові API, такі як OpenAI, Anthropic або Hugging Face TGI (Inference генерації тексту). LLM налаштовується за допомогою параметрів конфігурації `LLM_MODEL` та `LLM_BASE_URL`.

Крім API, сумісних з OpenAI, можна використовувати специфічні для постачальника префікси моделей Pydantic AI для OpenAI, Anthropic, Google, Mistral, Groq, AWS Bedrock та Ollama. Інші постачальники, такі як Cohere, Hugging Face та xAI, не встановлені; проте провайдери Hugging Face Inference все ще можуть використовуватися через їх сумісну з OpenAI кінцеву точку (`LLM_BASE_URL` встановлено на `https://router.huggingface.co/v1`).

Якщо ваш сервер моделі не обмежує довжину відповіді, встановіть `LLM_MAX_OUTPUT_TOKENS` на максимальну кількість токенів, які модель може згенерувати за одну відповідь (див. [Конфігурація](configuration.md)).

### Використання хостингової LLM через OpenAI API

При використанні OpenAI API `LLM_BASE_URL` можна залишити незадано, тоді як `LLM_MODEL` потрібно встановити на одну з моделей OpenAI, наприклад, `gpt-4o-mini`. LLM використовує виклик інструментів для відповіді на запитання: вона безпосередньо запитує базу даних, використовуючи спеціалізовані інструменти, і відповідає на основі записів, які вона знаходить. Це не вимагає глибоких генеалогічних або історичних знань. Тому ви можете спробувати, чи достатньо невеликої/дешевої моделі.

Вам також потрібно зареєструвати обліковий запис, отримати API-ключ і зберегти його в змінній середовища `OPENAI_API_KEY`.

!!! info
    `LLM_MODEL` є параметром конфігурації; якщо ви хочете встановити його через змінну середовища, використовуйте `GRAMPSWEB_LLM_MODEL` (див. [Конфігурація](configuration.md)). `OPENAI_API_KEY` не є параметром конфігурації, а є змінною середовища, яка безпосередньо використовується бібліотекою Pydantic AI, тому її не слід префіксувати.

### Використання Mistral AI

Щоб використовувати хостингові моделі Mistral AI, префіксуйте ім'я моделі `mistral:` при налаштуванні `LLM_MODEL`.

Вам потрібно буде зареєструвати обліковий запис Mistral AI, отримати API-ключ і зберегти його в змінній середовища `MISTRAL_API_KEY`. Немає необхідності встановлювати `LLM_BASE_URL`, оскільки Pydantic AI автоматично використовуватиме правильну кінцеву точку API Mistral.

Приклад конфігурації при використанні docker compose з змінними середовища:
```yaml
environment:
  GRAMPSWEB_LLM_MODEL: mistral:mistral-large-latest
  MISTRAL_API_KEY: your-mistral-api-key-here
```

### Використання локальної LLM через Ollama

[Ollama](https://ollama.com/) є зручним способом запуску LLM локально. Будь ласка, зверніться до документації Ollama для деталей. Зверніть увагу, що LLM вимагають значних обчислювальних ресурсів, і всі, крім найменших моделей, ймовірно, будуть занадто повільними без підтримки GPU. Оскільки асистент покладається на виклик інструментів, виберіть модель, яка підтримує інструменти, наприклад, [`qwen2.5`](https://ollama.com/library/qwen2.5). Почніть з невеликого варіанту, такого як `qwen2.5:7b`, і спробуйте більший, якщо відповіді не достатньо хороші. Будь ласка, поділіться будь-яким досвідом з громадою!

При розгортанні Gramps Web з Docker Compose ви можете додати сервіс Ollama і вказати Gramps Web на нього:

```yaml
services:
  grampsweb: &grampsweb
    # ... існуюча конфігурація ...
    environment:
      GRAMPSWEB_LLM_MODEL: ollama:qwen2.5:7b
      GRAMPSWEB_LLM_BASE_URL: http://ollama:11434/v1/

  grampsweb_celery: &grampsweb_celery
    # ... існуюча конфігурація ...
    environment:
      GRAMPSWEB_LLM_MODEL: ollama:qwen2.5:7b
      GRAMPSWEB_LLM_BASE_URL: http://ollama:11434/v1/

  ollama:
    image: ollama/ollama
    container_name: ollama
    ports:
      - "11434:11434"
    volumes:
      - ollama_data:/root/.ollama

volumes:
  ollama_data:
```

Після запуску сервісів, завантажте модель в Ollama:

```bash
docker compose exec ollama ollama pull qwen2.5:7b
```

Декілька моментів, які слід врахувати:

- Встановіть `LLM_MODEL` на ім'я моделі Ollama, включаючи її тег (частину після двокрапки, наприклад, `7b`), префіксуючи його `ollama:`. Префікс змушує Pydantic AI використовувати специфічні налаштування для моделі Ollama, що є рекомендованою конфігурацією.
- `LLM_BASE_URL` повинен закінчуватися на `/v1/`, наприклад, `http://ollama:11434/v1/`.
- З префіксом `ollama:` не потрібні ні `OPENAI_API_KEY`, ні змінна середовища `OLLAMA_BASE_URL`. Якщо `LLM_BASE_URL` не встановлено, Gramps Web повертається до `OLLAMA_BASE_URL`.
- Альтернативно, ви можете пропустити префікс (наприклад, `LLM_MODEL: qwen2.5:7b`) і використовувати Ollama через його загальний API, сумісний з OpenAI. У цьому випадку вам також потрібно встановити змінну середовища `OPENAI_API_KEY` на `ollama` (будь-яке ненульове значення працює).

Щоб усунути проблеми з Ollama, ви можете увімкнути журналювання налагодження, встановивши змінну середовища `OLLAMA_DEBUG=1` у середовищі сервісу Ollama.

!!! info
    Якщо ви використовуєте Ollama для AI чату Gramps Web, будь ласка, підтримайте громаду, доповнивши цю документацію будь-якими відсутніми деталями.

### Використання інших постачальників

Будь ласка, не соромтеся надсилати документацію для інших постачальників і ділитися своїм досвідом з громадою!

## Додаткові функції

### Зображення в запитаннях

Якщо ваша модель приймає зображення, встановіть `LLM_VISION` на `True`, щоб дозволити користувачам додавати зображення до своїх запитань, наприклад, скани записів (Gramps Web API 3.26+). Зображення зменшуються до максимум 1568 пікселів на довгій стороні перед відправкою до моделі. Перевірте, чи модель дійсно підтримує введення зображень: багато маленьких локальних моделей цього не роблять, і постачальник тоді відхиляє запитання з зображеннями.

### Дозволити асистенту пропонувати зміни

З параметром `LLM_ALLOW_WRITE_PROPOSALS`, встановленим на `True` (Gramps Web API 3.26+), асистент може [пропонувати зміни до дерева](../user-guide/chat.md#letting-the-assistant-change-your-tree), які користувачі застосовують після їх перегляду. Сам асистент ніколи не записує в базу даних. Пропозиції пропонуються лише користувачам, які мають право додавати, редагувати та видаляти об'єкти, тобто редакторам та вище, і які мають право використовувати чат.

Написання правильних пропозицій є складнішим для моделі, ніж відповіді на запитання, тому протестуйте це з вашою моделлю перед увімкненням для ваших користувачів. Додаткові інструменти також роблять кожен запит до моделі дещо більшим.
