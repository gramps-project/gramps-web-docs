# Налаштування AI чату

!!! info
    AI чат вимагає Gramps Web API версії 2.5.0 або вище. Версія 3.6.0 впровадила можливості виклику інструментів для більш інтелектуальних взаємодій.

Gramps Web API підтримує запитання про генеалогічну базу даних, використовуючи великі мовні моделі (LLM) з викликом інструментів.

## Як це працює

AI асистент використовує спеціалізовані інструменти для запиту ваших генеалогічних даних безпосередньо. Ці інструменти дозволяють асистенту шукати в базі даних за допомогою повнотекстового пошуку, фільтрувати людей/події/сім'ї/місця за конкретними критеріями, обчислювати стосунки між особами та отримувати повні записи, включаючи нотатки. Асистент відповідає на основі записів, які він знайшов, і надає посилання на них у своїй відповіді. Він відповідає лише з дерева, а не з загальних знань: якщо дерево не фіксує щось, асистент про це повідомляє. Посилання на об'єкти, які не існують або є приватними для користувача, замінюються їх текстом.

AI чат не потребує моделі векторного вбудовування. Версії Gramps Web API до 3.24 також використовували *семантичний пошук* (пошук з підсиленням отримання, RAG), який порівнював значення запитання з індексом числових векторів, обчислених для всіх об'єктів у базі даних. Семантичний пошук був видалений у Gramps Web API 3.25; параметри `VECTOR_EMBEDDING_MODEL`, `VECTOR_EMBEDDING_BASE_URL` та `VECTOR_EMBEDDING_API_KEY` ігноруються і можуть бути видалені з вашої конфігурації.

Щоб увімкнути кінцеву точку чату в Gramps Web API, необхідно виконати два кроки:

1. Встановлення необхідних залежностей,
2. Налаштування постачальника LLM.

Обидва кроки описані нижче по черзі. Нарешті, власник або адміністратор повинен [налаштувати, які користувачі можуть отримати доступ до функції чату](users.md#configuring-who-can-use-ai-chat) у налаштуваннях Управління користувачами.

## Встановлення необхідних залежностей

Стандартні образи Docker для Gramps Web вже мають усі необхідні залежності для AI чату попередньо встановленими.

При встановленні Gramps Web API через `pip` (це не потрібно при використанні образів Docker) необхідні залежності встановлюються з

```bash
pip install gramps_webapi[ai]
```

## Налаштування постачальника LLM

Зв'язок з LLM використовує фреймворк Pydantic AI, який підтримує API, сумісні з OpenAI. Це дозволяє використовувати локально розгорнуту LLM через Ollama (див. [Сумісність Ollama з OpenAI](https://ollama.com/blog/openai-compatibility)) або хостингові API, такі як OpenAI, Anthropic або Hugging Face TGI (Text Generation Inference). LLM налаштовується через параметри конфігурації `LLM_MODEL` та `LLM_BASE_URL`.

Окрім API, сумісних з OpenAI, можна використовувати специфічні для постачальника префікси моделей Pydantic AI для OpenAI, Anthropic, Google, Mistral, Groq, AWS Bedrock та Ollama. Інші постачальники, такі як Cohere, Hugging Face та xAI, не встановлені; постачальники Hugging Face Inference все ще можуть бути використані через їх сумісну з OpenAI кінцеву точку (`LLM_BASE_URL` встановлено на `https://router.huggingface.co/v1`).

Якщо ваш сервер моделі не обмежує довжину відповіді, встановіть `LLM_MAX_OUTPUT_TOKENS` на максимальну кількість токенів, які модель може згенерувати за одну відповідь (див. [Конфігурація](configuration.md)).

### Використання хостингової LLM через OpenAI API

При використанні OpenAI API, `LLM_BASE_URL` можна залишити незадіяним, тоді як `LLM_MODEL` потрібно встановити на одну з моделей OpenAI, наприклад, `gpt-4o-mini`. LLM використовує виклик інструментів для відповіді на запитання: вона безпосередньо запитує базу даних, використовуючи спеціалізовані інструменти, і відповідає на основі записів, які вона знаходить. Їй не потрібно глибоке генеалогічне або історичне знання. Тому ви можете спробувати, чи достатньо маленької/дешевої моделі.

Вам також потрібно зареєструватися для отримання облікового запису, отримати API ключ і зберегти його в змінній середовища `OPENAI_API_KEY`.

!!! info
    `LLM_MODEL` є параметром конфігурації; якщо ви хочете встановити його через змінну середовища, використовуйте `GRAMPSWEB_LLM_MODEL` (див. [Конфігурація](configuration.md)). `OPENAI_API_KEY` не є параметром конфігурації, а є змінною середовища, яку безпосередньо використовує бібліотека Pydantic AI, тому її не слід префіксувати.

### Використання Mistral AI

Щоб використовувати хостингові моделі Mistral AI, префіксуйте назву моделі `mistral:` при налаштуванні `LLM_MODEL`.

Вам потрібно зареєструватися для отримання облікового запису Mistral AI, отримати API ключ і зберегти його в змінній середовища `MISTRAL_API_KEY`. Немає потреби встановлювати `LLM_BASE_URL`, оскільки Pydantic AI автоматично використовуватиме правильну кінцеву точку API Mistral.

Приклад конфігурації при використанні docker compose з змінними середовища:
```yaml
environment:
  GRAMPSWEB_LLM_MODEL: mistral:mistral-large-latest
  MISTRAL_API_KEY: your-mistral-api-key-here
```

### Використання локальної LLM через Ollama

[Ollama](https://ollama.com/) є зручним способом запуску LLM локально. Будь ласка, зверніться до документації Ollama для деталей. Зверніть увагу, що LLM вимагають значних обчислювальних ресурсів, і всі, крім найменших моделей, ймовірно, будуть занадто повільними без підтримки GPU. Оскільки асистент покладається на виклик інструментів, виберіть модель, яка підтримує інструменти, такі як [`qwen2.5`](https://ollama.com/library/qwen2.5). Почніть з маленької варіації, такої як `qwen2.5:7b`, і спробуйте більшу, якщо відповіді недостатньо хороші. Будь ласка, поділіться своїм досвідом з громадою!

При розгортанні Gramps Web з Docker Compose ви можете додати сервіс Ollama і вказати Gramps Web на нього:

```yaml
services:
  grampsweb: &grampsweb
    # ... існуюча конфігурація ...
    environment:
      GRAMPSWEB_LLM_MODEL: ollama:qwen2.5:7b
      GRAMPSWEB_LLM_BASE_URL: http://ollama:11434/v1/

  grampsweb_celery: &grampsweb_celery
    # ... існуюча конфігурація ...
    environment:
      GRAMPSWEB_LLM_MODEL: ollama:qwen2.5:7b
      GRAMPSWEB_LLM_BASE_URL: http://ollama:11434/v1/

  ollama:
    image: ollama/ollama
    container_name: ollama
    ports:
      - "11434:11434"
    volumes:
      - ollama_data:/root/.ollama

volumes:
  ollama_data:
```

Після запуску сервісів, завантажте модель в Ollama:

```bash
docker compose exec ollama ollama pull qwen2.5:7b
```

Декілька моментів, на які слід звернути увагу:

- Встановіть `LLM_MODEL` на назву моделі Ollama, включаючи її тег (частину після двокрапки, наприклад, `7b`), префіксуючи `ollama:`. Префікс змушує Pydantic AI використовувати свої специфічні налаштування для моделі Ollama, що є рекомендованою конфігурацією.
- `LLM_BASE_URL` має закінчуватися на `/v1/`, наприклад, `http://ollama:11434/v1/`.
- З префіксом `ollama:` не потрібні ні `OPENAI_API_KEY`, ні змінна середовища `OLLAMA_BASE_URL`. Якщо `LLM_BASE_URL` не встановлено, Gramps Web повертається до `OLLAMA_BASE_URL`.
- Альтернативно, ви можете пропустити префікс (наприклад, `LLM_MODEL: qwen2.5:7b`) і використовувати Ollama через його загальний API, сумісний з OpenAI. У цьому випадку вам також потрібно встановити змінну середовища `OPENAI_API_KEY` на `ollama` (будь-яке ненульове значення працює).

Щоб усунути проблеми з Ollama, ви можете увімкнути налагоджувальне ведення журналів, встановивши змінну середовища `OLLAMA_DEBUG=1` у середовищі сервісу Ollama.

!!! info
    Якщо ви використовуєте Ollama для AI чату Gramps Web, будь ласка, підтримайте громаду, доповнивши цю документацію будь-якими відсутніми деталями.
