# Налаштування AI чату

!!! info
    AI чат вимагає Gramps Web API версії 2.5.0 або вище. Версія 3.6.0 впровадила можливості виклику інструментів для більш інтелектуальних взаємодій.

Gramps Web API підтримує запитання про генеалогічну базу даних, використовуючи великі мовні моделі (LLM) з викликом інструментів.

## Як це працює

AI асистент використовує спеціалізовані інструменти для запиту ваших генеалогічних даних безпосередньо. Ці інструменти дозволяють асистенту шукати в базі даних за допомогою повнотекстового пошуку, фільтрувати людей/події/сім'ї/місця за конкретними критеріями, обчислювати стосунки між особами та отримувати повні записи, включаючи нотатки. Асистент потім відповідає на основі записів, які він знайшов, і надає посилання на них у своїй відповіді.

Починаючи з Gramps Web API 3.24, AI чат більше не вимагає моделі векторного вбудовування. Раніші версії також використовували *семантичний пошук* (пошук з підсиленням отримання, RAG), який порівнює значення запитання з індексом числових векторів, обчислених для всіх об'єктів у базі даних. Семантичний пошук застарілий і буде видалений у Gramps Web API 3.25, див. [Семантичний пошук (застарілий)](#semantic-search-deprecated) нижче.

Щоб активувати кінцеву точку чату в Gramps Web API, необхідно виконати два кроки:

1. Встановлення необхідних залежностей,
2. Налаштування постачальника LLM.

Обидва кроки описані нижче по черзі. Нарешті, власник або адміністратор повинен [налаштувати, які користувачі можуть отримати доступ до функції чату](users.md#configuring-who-can-use-ai-chat) у налаштуваннях Управління користувачами.

## Встановлення необхідних залежностей

Стандартні образи Docker для Gramps Web вже мають всі необхідні залежності для AI чату попередньо встановленими.

При встановленні Gramps Web API через `pip` (це не потрібно, якщо ви використовуєте образи Docker) необхідні залежності встановлюються за допомогою

```bash
pip install gramps_webapi[ai]
```

## Семантичний пошук (застарілий)

!!! warning "Семантичний пошук застарілий"
    Семантичний пошук застарілий з Gramps Web API 3.24 і буде видалений у версії 3.25. AI чат та [повнотекстовий пошук](../user-guide/search.md) не потребують його. Після видалення налаштування `VECTOR_EMBEDDING_MODEL` все ще приймається, але ігнорується. Якщо ви встановлюєте його лише для активації AI чату, ви можете видалити його зараз разом з іншими налаштуваннями `VECTOR_EMBEDDING_*`, що також зекономить пам'ять, необхідну для моделі вбудовування.

У решті цього розділу описується семантичний пошук для серверів, які все ще його використовують з Gramps Web API 3.24.

Якщо необхідні залежності встановлені, активація семантичного пошуку може бути такою ж простою, як налаштування параметра конфігурації `VECTOR_EMBEDDING_MODEL` (наприклад, шляхом налаштування змінної середовища `GRAMPSWEB_VECTOR_EMBEDDING_MODEL`), див. [Конфігурація сервера](configuration.md). Це може бути будь-який рядок моделі, підтримуваної бібліотекою [Sentence Transformers](https://sbert.net/). Дивіться документацію цього проекту для деталей та доступних моделей.

!!! warning
    Зверніть увагу, що стандартні образи Docker не включають версію PyTorch з підтримкою GPU. Якщо у вас є доступ до GPU (що значно прискорить семантичну індексацію), будь ласка, встановіть версію PyTorch з підтримкою GPU.

Є кілька міркувань, які слід врахувати при виборі моделі.

- Коли ви змінюєте модель, вам потрібно вручну відтворити індекс семантичного пошуку для вашого дерева (або всіх дерев у багатодеревій конфігурації), інакше ви зіткнетеся з помилками або безглуздими результатами. Gramps Web виявляє, коли налаштована модель вбудовування більше не відповідає існуючому індексу, і показує постійне повідомлення адміністраторам, спонукаючи їх ініціювати повну повторну індексацію з [Налаштувань адміністрації](../administration/settings.md#semantic-search-index).
- Моделі є компромісом між точністю/узагальненням з одного боку та обчислювальним часом/обсягом пам'яті з іншого. Якщо ви не запускаєте Gramps Web API на системі, яка має доступ до потужного GPU, більші моделі зазвичай занадто повільні на практиці.
- Якщо ваша вся база даних англійською мовою і всі ваші користувачі лише очікуються задавати питання в чаті англійською, вам знадобиться багатомовна модель вбудовування, які є більш рідкісними, ніж чисто англійські моделі.

Якщо модель відсутня у локальному кеші, вона буде завантажена, коли Gramps Web API буде запущено вперше з новою конфігурацією. Модель `sentence-transformers/distiluse-base-multilingual-cased-v2` вже доступна локально при використанні стандартних образів Docker. Ця модель є хорошою відправною точкою і підтримує багатомовний ввід.

Будь ласка, діліться знаннями про різні моделі з громадою!

!!! info
    Бібліотека sentence transformers споживає значну кількість пам'яті, що може призвести до завершення роботи процесів. Як правило, при активованому семантичному пошуку кожен процес Gunicorn споживає близько 200 МБ пам'яті, а кожен процес celery близько 500 МБ пам'яті навіть у простої, і до 1 ГБ під час обчислення вбудовувань. Дивіться [Обмеження використання CPU та пам'яті](cpu-limited.md) для налаштувань, які обмежують використання пам'яті. Крім того, рекомендується виділити достатньо великий розділ підкачки, щоб запобігти помилкам OOM через тимчасові сплески використання пам'яті.

### Використання віддаленого API вбудовування

Як альтернатива запуску локальної моделі Sentence Transformers, ви можете використовувати віддалений API вбудовування, сумісний з OpenAI, для семантичного пошуку. Це корисно, якщо ви хочете зменшити навантаження на обчислення вбудовувань на окремий сервіс (наприклад, [Ollama](https://ollama.com/)), використовувати хмарного постачальника вбудовування (наприклад, OpenAI) або уникнути завантаження бібліотек Sentence Transformers і PyTorch у пам'ять.

Віддалений API повинен бути сумісним з [кінцевою точкою вбудовувань OpenAI](https://platform.openai.com/docs/api-reference/embeddings) (`/v1/embeddings`).

Щоб використовувати віддалений API вбудовування, налаштуйте наступні параметри конфігурації (див. [Конфігурація сервера](configuration.md)):

Ключ | Опис
----|-------------
`VECTOR_EMBEDDING_MODEL` | Назва моделі, яку потрібно передати віддаленому постачальнику
`VECTOR_EMBEDDING_BASE_URL` | Базова URL-адреса віддаленого API
`VECTOR_EMBEDDING_API_KEY` | API ключ (потрібен лише, якщо постачальник вимагає автентифікації)

#### Використання Ollama для вбудовувань

При розгортанні Gramps Web за допомогою Docker Compose, ви можете додати сервіс Ollama і використовувати його як для вбудовувань, так і (за бажанням) для LLM:

```yaml
services:
  grampsweb: &grampsweb
    # ... існуюча конфігурація ...
    environment:
      GRAMPSWEB_VECTOR_EMBEDDING_MODEL: nomic-embed-text
      GRAMPSWEB_VECTOR_EMBEDDING_BASE_URL: http://ollama:11434

  grampsweb_celery: &grampsweb_celery
    # ... існуюча конфігурація ...
    environment:
      GRAMPSWEB_VECTOR_EMBEDDING_MODEL: nomic-embed-text
      GRAMPSWEB_VECTOR_EMBEDDING_BASE_URL: http://ollama:11434

  ollama:
    image: ollama/ollama
    container_name: ollama
    ports:
      - "11434:11434"
    volumes:
      - ollama_data:/root/.ollama

volumes:
  ollama_data:
```

Після запуску сервісів, завантажте модель в Ollama:

```bash
docker compose exec ollama ollama pull nomic-embed-text
```

!!! info
    Коли ви використовуєте Ollama для вбудовувань, бібліотеки Sentence Transformers і PyTorch не потрібні, що значно зменшує використання пам'яті процесами Gramps Web API.

#### Використання OpenAI для вбудовувань

Щоб використовувати API вбудовувань OpenAI, встановіть базову URL-адресу на API OpenAI та надайте свій API ключ:

```yaml
environment:
  GRAMPSWEB_VECTOR_EMBEDDING_MODEL: text-embedding-3-small
  GRAMPSWEB_VECTOR_EMBEDDING_BASE_URL: https://api.openai.com
  GRAMPSWEB_VECTOR_EMBEDDING_API_KEY: sk-...
```

!!! warning
    Зміна моделі вбудовування вимагає повторної індексації всіх записів для вашого дерева (або всіх дерев у багатодеревій конфігурації), оскільки різні моделі виробляють вектори з різними розмірами.

## Налаштування постачальника LLM

Зв'язок з LLM використовує фреймворк Pydantic AI, який підтримує API, сумісні з OpenAI. Це дозволяє використовувати локально розгорнуту LLM через Ollama (див. [Сумісність Ollama з OpenAI](https://ollama.com/blog/openai-compatibility)) або хостингові API, такі як OpenAI, Anthropic або Hugging Face TGI (Inference текстового генератора). LLM налаштовується через параметри конфігурації `LLM_MODEL` і `LLM_BASE_URL`.

### Використання хостингової LLM через API OpenAI

При використанні API OpenAI, `LLM_BASE_URL` можна залишити незадано, тоді як `LLM_MODEL` потрібно встановити на одну з моделей OpenAI, наприклад, `gpt-4o-mini`. LLM використовує виклик інструментів для відповіді на запитання: він безпосередньо запитує базу даних, використовуючи спеціалізовані інструменти, і відповідає на основі записів, які він знаходить. Він не вимагає глибоких генеалогічних або історичних знань. Тому ви можете спробувати, чи достатньо маленької/дешевої моделі.

Вам також потрібно буде зареєструвати обліковий запис, отримати API ключ і зберегти його у змінній середовища `OPENAI_API_KEY`.

!!! info
    `LLM_MODEL` є параметром конфігурації; якщо ви хочете встановити його через змінну середовища, використовуйте `GRAMPSWEB_LLM_MODEL` (див. [Конфігурація](configuration.md)). `OPENAI_API_KEY` не є параметром конфігурації, а є змінною середовища, яка безпосередньо використовується бібліотекою Pydantic AI, тому її не слід префіксувати.

### Використання Mistral AI

Щоб використовувати хостингові моделі Mistral AI, префіксуйте назву моделі `mistral:` при налаштуванні `LLM_MODEL`.

Вам потрібно буде зареєструвати обліковий запис Mistral AI, отримати API ключ і зберегти його у змінній середовища `MISTRAL_API_KEY`. Немає потреби встановлювати `LLM_BASE_URL`, оскільки Pydantic AI автоматично використовуватиме правильну кінцеву точку API Mistral.

Приклад конфігурації при використанні docker compose з змінними середовища:
```yaml
environment:
  GRAMPSWEB_LLM_MODEL: mistral:mistral-large-latest
  MISTRAL_API_KEY: ваш-ключ-api-mistral-тут
```

### Використання локальної LLM через Ollama

[Ollama](https://ollama.com/) є зручним способом запуску LLM локально. Будь ласка, ознайомтеся з документацією Ollama для деталей. Зверніть увагу, що LLM вимагають значних обчислювальних ресурсів, і всі, крім найменших моделей, ймовірно, будуть занадто повільними без підтримки GPU. Оскільки асистент покладається на виклик інструментів, виберіть модель, яка підтримує інструменти, такі як [`qwen2.5`](https://ollama.com/library/qwen2.5). Почніть з маленького варіанту, як `qwen2.5:7b`, і спробуйте більший, якщо відповіді не достатньо хороші. Будь ласка, діліться будь-яким досвідом з громадою!

При розгортанні Gramps Web за допомогою Docker Compose, ви можете додати сервіс Ollama і вказати Gramps Web на нього:

```yaml
services:
  grampsweb: &grampsweb
    # ... існуюча конфігурація ...
    environment:
      GRAMPSWEB_LLM_MODEL: ollama:qwen2.5:7b
      GRAMPSWEB_LLM_BASE_URL: http://ollama:11434/v1/

  grampsweb_celery: &grampsweb_celery
    # ... існуюча конфігурація ...
    environment:
      GRAMPSWEB_LLM_MODEL: ollama:qwen2.5:7b
      GRAMPSWEB_LLM_BASE_URL: http://ollama:11434/v1/

  ollama:
    image: ollama/ollama
    container_name: ollama
    ports:
      - "11434:11434"
    volumes:
      - ollama_data:/root/.ollama

volumes:
  ollama_data:
```

Після запуску сервісів, завантажте модель в Ollama:

```bash
docker compose exec ollama ollama pull qwen2.5:7b
```

Кілька моментів, які слід врахувати:

- Встановіть `LLM_MODEL` на назву моделі Ollama, включаючи її тег (частину після двокрапки, наприклад, `7b`), префіксуючи `ollama:`. Префікс змушує Pydantic AI використовувати специфічні для Ollama налаштування для моделі, що є рекомендованою конфігурацією.
- `LLM_BASE_URL` повинен закінчуватися на `/v1/`, наприклад, `http://ollama:11434/v1/`.
- З префіксом `ollama:` не потрібні ні `OPENAI_API_KEY`, ні змінна середовища `OLLAMA_BASE_URL`. Якщо `LLM_BASE_URL` не встановлено, Gramps Web повертається до `OLLAMA_BASE_URL`.
- Альтернативно, ви можете залишити префікс (наприклад, `LLM_MODEL: qwen2.5:7b`) і використовувати Ollama через його загальний API, сумісний з OpenAI. У цьому випадку вам також потрібно буде встановити змінну середовища `OPENAI_API_KEY` на `ollama` (будь-яке ненульове значення працює).

Щоб усунути проблеми з Ollama, ви можете активувати журналювання налагодження, встановивши змінну середовища `OLLAMA_DEBUG=1` у середовищі сервісу Ollama.

!!! info
    Якщо ви використовуєте Ollama для AI чату Gramps Web, будь ласка, підтримайте громаду, завершивши цю документацію будь-якими відсутніми деталями.
