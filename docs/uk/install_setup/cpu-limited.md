# Обмеження використання CPU та пам'яті

У рекомендованій конфігурації на базі Docker, Gramps Web використовує [Gunicorn](https://gunicorn.org/) для обслуговування
бекенду та [Celery](https://docs.celeryq.dev) для фонових завдань. У обох випадках кілька робочих
процесів можуть працювати паралельно, що робить застосунок більш чутливим з точки зору користувача.
Однак збільшення кількості робочих процесів також збільшує обсяг використаної оперативної пам'яті (навіть коли застосунок неактивний)
і дозволяючи запитам оброблятись паралельно, це може призвести до високого використання CPU (особливо коли багато користувачів
використовують застосунок одночасно). Як Gunicorn, так і Celery дозволяють обмежити кількість паралельних робочих процесів.

## Отримання інформації про вашу систему

На Linux ви можете перевірити кількість доступних ядер на вашій системі за допомогою наступної команди:

```bash
lscpu | grep CPU
```

Щоб дізнатися, скільки пам'яті та простору підкачки у вас доступно, використовуйте

```bash
free -h
```


## Обмеження кількості робочих процесів Gunicorn

Найпростіший спосіб встановити кількість робочих процесів Gunicorn при використанні стандартного образу Gramps Web
Docker — це встановити змінну середовища `GUNICORN_NUM_WORKERS`, наприклад, оголосивши її
в файлі `docker-compose.yml`,
під розділом "environment".

```yaml
services:
  grampsweb:
    environment:
      GUNICORN_NUM_WORKERS: 2
```

Дивіться [документацію Gunicorn](https://docs.gunicorn.org/en/stable/design.html#how-many-workers), щоб визначити
ідеальну кількість робочих процесів.

!!! info
    Образ Docker запускає Gunicorn з параметром `--preload`, тому робочі процеси ділять пам'ять завантаженого застосунку, і кожен додатковий робочий процес потребує менше пам'яті. Якщо ви переоприділяєте команду Gunicorn, зберігайте `--preload`, щоб скористатися цим.



## Обмеження кількості робочих процесів Celery

Щоб встановити кількість робочих процесів Celery, адаптуйте налаштування `concurrency` у файлі Docker compose:

```yaml
  grampsweb_celery:
    command: celery -A gramps_webapi.celery worker --loglevel=INFO --concurrency=2
```

Дивіться [документацію Celery](https://docs.celeryq.dev/en/stable/userguide/workers.html#concurrency), щоб визначити
ідеальну кількість робочих процесів.

!!! info
    Якщо прапорець `concurrency` пропущено (що було у документації Gramps Web до версії 2.5.0), він
    за замовчуванням дорівнює кількості доступних ядер CPU на системі, що може споживати значну кількість пам'яті.
