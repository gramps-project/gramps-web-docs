# Налаштування для хостингу кількох дерев

За замовчуванням Gramps Web дозволяє доступ лише до однієї бази даних родинного дерева ("дерево"), що вказується у файлі конфігурації.

Однак, починаючи з версії 0.7.0 бекенду Gramps Web API, також можливо обслуговувати кілька дерев з однієї установки. Проте, кожен користувач (наразі) прив'язаний до одного дерева, тому це налаштування не підходить для спільного використання дерев між користувачами, а призначене для хостингу кількох ізольованих екземплярів Gramps Web.

## Увімкнення підтримки кількох дерев

Щоб увімкнути підтримку кількох дерев, параметр конфігурації `TREE` потрібно встановити на один символ зірочки `*`, наприклад, у файлі конфігурації:

```python
TREE = "*"
```

Це зробить всі дерева в директорії бази даних Gramps сервера доступними (за умови наявності достатніх прав користувача). ID дерева - це назва підкаталогу. Ви можете перерахувати існуючі дерева (імена та ID) за допомогою команди

```bash
python -m gramps_webapi --config /app/config/config.cfg tree list
```

Крім того, вам слід встановити параметр конфігурації `MEDIA_PREFIX_TREE` на `True`, щоб забезпечити зберігання медіафайлів у окремих підкаталогах. В іншому випадку, користувачі можуть отримати доступ до медіафайлів, які належать дереву, до якого у них немає дозволу!

## Додати обліковий запис користувача до конкретного дерева

Щоб додати користувача до конкретного дерева, просто додайте параметр командного рядка `--tree TREEID` до команди додавання користувача. Ви також можете надіслати POST запит до кінцевої точки `/users/` з властивістю `tree`, встановленою в JSON-вантажі.

Імена користувачів повинні бути унікальними для *всіх* дерев. Адреси електронної пошти не повинні бути унікальними (з версії Gramps Web API 3.22), тому одна й та ж особа може, наприклад, мати облікові записи в кількох деревах, використовуючи одну електронну адресу.

## Створити нове дерево

Щоб створити нове дерево, рекомендується надіслати POST запит до кінцевої точки `/trees/`, а не використовувати Gramps CLI. Це використає UUIDv4 як ID дерева, що забезпечує додаткову безпеку, оскільки назву не можна вгадати. Наразі підтримується лише SQLite для новостворених дерев.

## Авторизація

Для авторизації (отримання токена) необхідні лише ім'я користувача та пароль, як у режимі одного дерева, оскільки ID дерева відомий для кожного користувача, тому немає необхідності його вказувати.

## Міграція існуючих медіафайлів

Якщо ви хочете мігрувати існуючий екземпляр Gramps Web до підтримки кількох дерев і використовуєте локальні медіафайли, ви можете просто перемістити їх до підкаталогу оригінального місця з ID дерева як назвою.

Якщо ви використовуєте медіафайли, розміщені на S3, ви можете скористатися скриптом, наданим у директорії `scripts` репозиторію `gramps-web-api`:

```bash
python scripts/s3_rename.py BUCKET_NAME TREE_ID
```

Це передбачає, що відповідні ключі доступу вже встановлені як змінні середовища.

## Міграція існуючої бази даних користувачів

Якщо ви хочете увімкнути підтримку кількох дерев і повторно використовувати існуючих користувачів, вам потрібно призначити їх до конкретного дерева. Ви можете використовувати наступну команду, надану для цієї мети,

```bash
python -m gramps_webapi --config /app/config/config.cfg user fill-tree TREE_ID
```

## Налаштування фронтенду

Сторінка реєстрації, доступна з сторінки входу, не працює в налаштуванні з кількома деревами, оскільки дерево потрібно вказати для реєстрації. Тому доцільно встановити `hideRegisterLink` на `true` у [конфігурації фронтенду](frontend-config.md).
